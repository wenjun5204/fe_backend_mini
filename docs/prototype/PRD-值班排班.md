## 1. 背景与机会

### 1.1 竞品洞察

对市面头部排班小程序（如「极简排班」）的体验分析结论：**排班产品的共性痛点在"协作"，而不在"记录"**。

| 竞品痛点 | 具体表现 |
|---|---|
| 日历可读性差 | 班次压缩为日期格内竖排小字，不点开看不清 |
| 提醒粒度粗 | 仅"提前 1 天 12:00"一种，夜班场景形同虚设 |
| 周期规则配置繁琐 | 需要看视频教程才能上手，规则藏在二级 Tab |
| 无导入能力 | 老用户手上的 Excel/纸面排班表无法迁移 |
| 换班协作缺失 | 换班靠口头约定，改表全靠管理员手动 |
| 数据保留焦虑 | 免费版数据限时清理，入口直接暴露在"我的"页 |

### 1.2 我们的机会：反向切入

竞品做的是"**给班组长的排班工具**"（多人协作、复杂规则）。我们做反向轻量切面：

> **"我的值班日历"——个人视角的值班记录与提醒工具，天然融入念家时的"日子"心智。**

- 念家时的核心资产是**日期数据结构 + 提醒链路（订阅消息）+ 情感化设计**，值班场景可完全复用
- 目标场景：护士、保安、工厂轮班工人、门店店员等轮班人群，**记录自己的班**并**不忘记哪天要上班**；家人之间也可以互相查看"他今天值不值班"
- 不做：团队排班管理、换班审批、薪水和工时核算（竞品红海，且与产品心智冲突）

### 1.3 战略路径：先内嵌验证，后独立拆分

| 阶段 | 动作 | 判断标准（上线 4 周后） |
|---|---|---|
| Phase 1（本 PRD） | 念家时新增「值班」Tab，验证需求 | 满足下述拆分信号 ≥ 2 条 |
| Phase 2 | 数据达标 → 拆独立小程序，代码平移 | — |

**拆分信号**：
1. 值班功能周活跃用户占小程序日活 30%+；
2. 值班用户次日留存显著高于纯纪念日用户（+5pp 以上）；
3. 新增用户中来自值班页分享的占比 > 20%；
4. 用户反馈集中出现"团队排班 / 换班"协作诉求。

## 2. 目标用户与场景

| 画像 | 场景 | 核心诉求 |
|---|---|---|
| 轮班工作者（主） | 护士小周，四班三运转，总记不清"明天是早班还是夜班" | 一眼看到今天/明天班次，上班前被提醒 |
| 倒班家属 | 女儿想确认"爸爸这周六值不值班，能不能来家吃饭" | 分享值班表给家人，或设置"值班的日程"对家人可见 |
| 做一休一人群 | 门卫老李，做一休一 | 一次配置循环规则，之后不用管 |

---

## 3. 设计原则

1. **不学习成本**：所有高频操作（设班次、配规则）1 步完成，不出现"需要教程"的功能
2. **一眼可读**：日历格子内班次标签横向可读、颜色区分明显（对比竞品竖排小字）
3. **复用优先**：日期存储、订阅消息、视觉规范全部复用念家时现有体系，值班页放分包
4. **克制**：MVP 不做协作、不做薪资，避免功能与"念家时"心智冲突

## 4. 信息架构与入口

### 4.1 TabBar 变更

现有 4 个 Tab（日子 / 家人 / 模板馆 / 我的）扩展为 5 个：

| Tab | 内容 | 状态 |
|---|---|---|
| 日子 | 纪念日/倒数日首页 | 已有 |
| 家人 | 家庭空间 | 已有 |
| **值班** | **本 PRD 新增** | **新增** |
| 模板馆 | 卡片模板 | 已有 |
| 我的 | 设置 | 已有 |

- Tab 名称定为「**值班**」（非"排班"），降低"这是另一个工具 App"的违和感
- 页面路径：分包 `subpackages/duty/pages/calendar/calendar`（避免主包体积超限）
- 若 TabBar 5 项视觉过挤的备选方案：不新增 Tab，改为「日子」页顶部入口 + 首次访问引导弹窗（评审时决策）

### 4.2 页面结构（自上而下）

```
┌─────────────────────────────┐
```

## 5. 功能需求详述

> 优先级：P0 = MVP 必须；P1 = 快速跟进；P2 = 视数据决定

### 5.1 班次体系（P0）

| 项 | 规格 |
|---|---|
| 默认班次 | 早班（08:00–17:00）、中班（12:00–24:00）、夜班（20:00–次日08:00）、休 |
| 标识 | 日历内显示单字：早 / 中 / 夜 / 休 |
| 配色 | 早 = 主题玫红 `#ff4d6d`，中 = 橙 `#e8943a`，夜 = 藏蓝 `#3d4a5c`，休 = 灰 `#c8cdd3` |
| 自定义班次 | **MVP 不支持**（P2 评估：自定义名称 + 时段 + 颜色） |

### 5.2 今日状态卡（P0）

- 显示今日日期与星期、今日班次（"今日早班 / 今日休班 😴 / 今日无排班"）
- **下次值班倒计时**：向后扫描 60 天内最近一个非"休"的排班日，显示"距下次值班还有 N 天 + 日期 + 班次"；无排班显示"近期暂无值班安排"
- 右上角「🔔 提醒」入口 → 提醒设置弹层（见 5.6）

### 5.3 月历视图（P0）

- 周一为首日；支持 ‹ › 翻月，默认当前月
- 每个日期格：日期数字 + 班次色块标签；今日描边高亮
- 点击任意日期 → 单日编辑弹层：
  - 四个班次选项（点选即保存，Toast 反馈）
  - 「清除这一天」
  - 引导文案指向批量排班
- 非本月日期置灰不可点

### 5.4 批量排班 / 周期规则（P0，核心卖点）

弹层字段：

| 字段 | 规格 |
|---|---|
| 开始日期 | date picker，默认下月 1 号 |
| 截止日期 | date picker，默认下月月末 |
| 规则 | 5 个预设 chip（见下表），单选 |

| 预设规则 | 循环序列 | 说明 |
|---|---|---|
| 每天早班 | [早] | 最简场景兜底 |
| 做一休一 | [早, 休] | 最高频轮班模式 |
| 做二休二 | [早, 早, 休, 休] | |
| 早→中→夜→休 | [早, 中, 夜, 休] | 四班三运转近似 |
| 每周五值班 | 星期五 → 早班 | 每周固定日模式 |

- 应用逻辑：从开始日起按序列循环填充至截止日；「每周 X」模式按星期匹配填充
- **覆盖提示**：范围内已有排班将被覆盖，应用前二次确认
- 应用结果 Toast：`已按「做一休一」排 N 天 ✓`
- P1：自定义循环序列（自选班次组合成 N 天循环）；"每周几"多选

### 5.5 本月统计条（P0）

- 展示当前视图月份的早班 / 夜班 / 休班次数
- P1：工时估算（按班次时段累计）、夜班连续天数警示（>3 天提示休息）

### 5.6 值班提醒（P0）

| 项 | 规格 |
|---|---|
| 提醒时机选项 | 提前 1 天 12:00（默认）/ 当天 08:00 / 提前 2 小时 |
| 触达方式 | 微信订阅消息（一次性订阅，按班次日期逐次请求授权） |
| 推送文案 | 「明天（10/31）早班 08:00 上班，别忘了～」 |
| 夜班建议 | 设置夜班班次时，若用户提醒为"当天 08:00"，提示改为"提前 2 小时" |
| 授权策略 | 用户保存规则后立即请求订阅授权；被拒后不重复弹，在状态卡显示"提醒未开启"弱引导 |

> 复用念家时现有订阅消息模板申请流程；如无合适类目模板，需新增申请。

### 5.7 分享（P1）

- 右上角菜单分享 + 状态卡长按分享
- 分享卡片：标题「我 11 月的值班表」/ 缩略图为月历截图
- 被分享者打开：只读月历视图，顶部显示"来自 XX 的值班表" + 「我也记值班」转化按钮（冷启动拉新核心链路）

### 5.8 数据导入（P2 评估）

- 拍照识别排班表（OCR）或 Excel 粘贴导入——解决竞品最大迁移痛点，但成本高，MVP 不做
- P2 简化版：文本粘贴（如"11/1 早 11/2 休"）按规则解析

## 6. 数据结构（概念模型）

```jsonc
// 班次记录（按用户 × 日期一条）
{
  "openid": "xxx",
  "date": "2026-11-01",        // 业务日期
  "shift": "early",            // early | mid | night | rest
  "source": "rule:duty_on1off1" | "manual",  // 来源，用于统计与撤销
  "updatedAt": 1793XXXXXXX
}
// 周期规则（用户级，单条生效，重新应用即覆盖）
{
  "openid": "xxx",
  "ruleType": "on1off1",       // daily | on1off1 | on2off2 | emnr | weekday
  "startDate": "2026-11-01",
  "endDate": "2026-11-30",
  "active": true
}
```

- 存储沿用念家时现有后端（云开发集合或自建，按现状接入）
- 单用户排班记录按月懒加载（首屏只拉当月 ± 1 月）

## 7. 交互细节与异常处理

| 场景 | 处理 |
|---|---|
| 未登录/未授权 | 沿用念家时统一登录态，静默 openid 授权 |
| 无任何排班数据 | 状态卡显示"今日无排班"，日历空白，主按钮高亮引导"从批量排班开始" |
| 应用规则日期跨度 > 1 年 | 截断至 365 天并 Toast 提示 |
| 翻月加载失败 | 日历区域局部 loading + 重试按钮，不阻塞全局 |
| 订阅消息授权被拒 | 不再弹窗，状态卡弱提示，可在"提醒"弹层重新开启 |
| 删除单日班次 | 仅清除该日记录，不影响周期规则本体（重新应用规则会回填） |

## 8. 埋点与验证指标

| 事件 | 参数 |
|---|---|
| duty_page_view | 来源（tab / share） |
| duty_day_edit | 班次类型 |
| duty_rule_apply | 规则类型、覆盖天数 |
| duty_remind_enable | 提醒时机 |
| duty_share | — |

**北极星指标**：周度「配好规则且开启提醒」的用户数。
辅助：值班页人均访问频次、规则应用后 7 日回访率、分享带来新增占比（对应 1.3 拆分信号）。

## 9. 非功能需求

- **分包加载**：值班页独立分包，首屏分包下载 < 300ms（P50）
- **性能**：月历渲染 ≤ 16ms/帧，无长列表
- **隐私**：值班数据仅本人与被分享者可见；隐私协议新增该功能说明
- **兼容**：基础库 ≥ 2.30；iOS/Android 日历渲染一致性走查

## 11. 本期明确不做

- 团队/成员管理、换班申请审批
- 薪水、加班、工时核算
- 自定义班次、 OCR 导入
- 桌面小组件（后续可作留存亮点）

## 12. 开放问题（评审需决策）

1. TabBar 第 5 项 vs 「日子」页入口（视觉拥挤度需 UI 走查确认）
2. 分享只读视图是否需要"家人互看值班"升级为家庭空间能力（涉及家人模块联动）
3. 班次默认时段是否提供"仅记录不上班时间"的极简模式
