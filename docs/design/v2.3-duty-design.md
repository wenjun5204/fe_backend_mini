## 1. 后端设计（backend/，原地演进）

### 1.1 数据库变更（3 张新表，ddl-auto=update 自动建列）

| 表 | 列 | 约束 |
|---|---|---|
| `duty_shift` | id PK / userId / dutyDate(LocalDate) / shift(early\|mid\|night\|rest) / source / updatedAt | uk(user_id, duty_date) |
| `duty_rule` | id PK / userId / ruleType / startDate / endDate / active / appliedDays / updatedAt | uk(user_id) 单条生效 |
| `duty_remind` | id PK / userId / timing / enabled / updatedAt | uk(user_id) |

- shift/timing/ruleType 均存字符串 + 服务层枚举校验（沿用 TemplateKey 先例：DB 层无 ENUM，规避 H2/MySQL ENUM 列扩值迁移坑，见 .agents/docs/architecture.md 踩坑教训）
- source 格式：`manual` 或 `rule:<ruleType>`
- LocalDate 映射：既有 DayRecordEntity 已用 LocalDate，沿用

### 1.2 Repository（3 新）

- `DutyShiftRepository`：`findByUserIdAndDutyDateBetweenOrderByDutyDateAsc`（月历/60 天扫描共用）、`findByUserIdAndDutyDate`、`deleteByUserIdAndDutyDate`
- `DutyRuleRepository`：`findByUserId`
- `DutyRemindRepository`：`findByUserId`

### 1.3 DutyService（全部业务）

- `getCalendar(month)`：解析 yyyy-MM → 该月 [首日, 末日] 区间查 shifts + 统计 stats；月缺省当月
- `getToday(date)`：今日 shift（findByUserIdAndDutyDate）+ nextDuty（明日+60 天区间内第一个非 rest，按日期升序取首个）+ remind 配置（无行=advance_1d/enabled=false）；date 参数缺省 LocalDate.now()
- `setShift(date, shift)`：upsert（有行改 shift+source=manual，无行新建）；返回 DutyShiftView
- `clearShift(date)`：deleteByUserIdAndDutyDate；幂等恒 cleared=true
- `getRule()`：读 duty_rule 行；无行返回 active=false/appliedDays=0 空壳
- `applyRule(ruleType, startDate, endDate)`：
  1. 校验 ruleType 枚举（40000）；startDate≤endDate（40000）
  2. 跨度>365 天：endDate=startDate+364，truncated=true
  3. 序列规则 daily/on1off1/on2off2/emnr：SEQUENCES 常量表取循环序列，逐日填充（含休班也写入——休是显式记录）
  4. weekday 规则：仅 startDate..endDate 内的星期五写 early，其余日不动
  5. 区间内已有行（不论来源）直接覆盖 shift+source
  6. 批量 saveAll + upsert duty_rule 行（ruleType/实际 endDate/appliedDays/active=true）
  7. 返回 appliedDays（weekday=命中天数）/truncated
- `updateRemindConfig(timing, enabled)`：校验枚举（40000）→ upsert duty_remind

**序列常量表**：`daily=[early]`、`on1off1=[early,rest]`、`on2off2=[early,early,rest,rest]`、`emnr=[early,mid,night,rest]`；`weekday` 单独分支（DayOfWeek.FRIDAY→early）。

### 1.4 事务矩阵（MySQL 严格模式铁律：readOnly 内零写库）

| 方法 | 事务 | 写库 |
|---|---|---|

## 2. 前端设计（miniprogram-nianjiashi/）

### 2.1 Tab 方案（裁定 D4）

TabBar 4→5 项：日子/家人/**值班**/模板馆/我的；值班插第 3 位。纯文字无 icon（现状同款），无 icon 资产需求；页面在主包 `pages/duty/duty`（微信 tab 页禁分包，主包 516K 体积无忧）。

### 2.2 页面结构（pages/duty/duty，自上而下对齐 PRD §4.2）

```
① 今日状态卡   date+星期 | 今日班次(早/休😴/无排班) | 下次值班倒计时 | 🔔提醒入口
② 班次图例     早=玫红#ff4d6d 中=橙#e8943a 夜=藏蓝#3d4a5c 休=灰#c8cdd3
③ 月历视图     周一首日 | ‹›翻月 | 7×6 格(日期数字+班次色块标签) | 今日描边 | 点击→单日编辑弹层
④ 本月统计条   早N 中N 夜N 休N
⑤ 主按钮       「批量排班」(一屏一主按钮,高≥88rpx)
```

**三个弹层**（页面内 wxml 条件渲染，不用新页面——任何功能≤3次点击）：

1. **单日编辑弹层**：四班次大按钮（点选即调 POST /api/duty/shifts，Toast「已设置明天早班」）+「清除这一天」（DELETE，幂等）+ 引导文案「要排一整月？试试批量排班」
2. **批量排班弹层**：开始/截止日期 picker（默认下月 1 号–月末）+ 5 规则 chip 单选 +「应用」→ 范围内有已有排班时 wx.showModal 二次确认（覆盖提示）→ POST /api/duty/rules/apply → Toast「已按『做一休一』排 N 天 ✓」（truncated 时改提示一年上限）
3. **提醒设置弹层**：时机三选一 + 开关保存 → PUT /api/duty/remind-config + wx.requestSubscribeMessage + POST /api/notify/subscribe 登记授权；今日/选中班次为夜班且当前 same_day_08 时提示改 advance_2h

### 2.3 数据流（utils/api-duty.js，7 端点封装）

```
onLoad/onShow:
  getDutyToday() ──→ 状态卡(今日+下次值班+remind)
  getDutyCalendar(当月/前月/后月) ──→ 月历缓存 {month: shiftsMap}  (首屏 3 并发)
翻月: 命中缓存直接渲染,未命中拉取+局部 loading+失败重试
单日编辑/批量排班落库后: 失效受影响月份缓存并重拉对应月+today
```

- shifts 以 `map[date]=shift` 存缓存，渲染时格子查表
- 月历矩阵生成纯前端（周一首日、非本月置灰不可点）
- 班次→单字/颜色映射表前端常量（早/中/夜/休 + PRD 配色）

## 3. 测试策略（后端，H2 内存库集成测试，沿用 MockMvc 先例）

`DutyApiIntegrationTest` 覆盖（目标 ≥25 条）：

1. **月历**：空月空 shifts+零 stats；设班后 shifts 升序+stats 计数；month 非法 40000
2. **今日状态卡**：无排班 todayShift=null；当日 early；nextDuty 60 天窗口扫描（含 rest 排除、今天不参与、61 天外不取、无值班 null）；date 注入时钟
3. **单日设置/清除**：upsert 覆盖（manual 覆盖 rule 来源）；清除幂等；shift 越值域 40000；date 非法 40000
4. **规则应用**：daily/on1off1/on2off2/emnr 各自序列断言（含区间内已有排班被覆盖）；weekday 只填星期五；endDate<startDate 40000；跨度>365 截断 truncated=true；规则行 upsert（重新应用整行覆盖+appliedDays 更新）；清除单日后重新应用回填
5. **提醒配置**：默认空壳；保存回显；timing 越值域 40000
6. **鉴权**：无 token 40100（7 端点全量）

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 批量应用写放大（365 行 upsert） | 单事务 saveAll，量级 H2/MySQL 均秒级；MVP 不做异步 |
| 5 Tab 小屏拥挤 | 5 项均 2 字纯文字，320pt 走查放 Stage 5B 自验清单 |
| 月历跨月缓存不一致（编辑后未失效） | 落库成功后统一失效受影响月份+today 重拉，写操作串行化在页面回调 |
| 夜班提醒时机组合不当 | 前端引导切换 advance_2h（PRD §5.6）；后端不强制（存用户意愿） |
