### 1.2 TemplateConfig：静态配置类还是表？——**裁定：代码内静态配置类 `TemplateCatalog`**

理由：① 无管理端点（需求 §2 明示「上下架由数据配置驱动，无管理端点」），表数据无人维护，改配置只能直连生产库——比发版更危险；② 预览元数据（sampleText/feats/usedLabel 等）是**用户可见文案**，合规红线要求过违禁词表断言——静态类可做**类加载期断言**（沿 `DayTextLib` 机制，违禁词出现即启动失败），表数据做不到；③ 模板上下架/节日日期是低频运营动作（月级），随代码版本管理可审计可回滚，云托管发版即生效；④ 避免 H2/MySQL 种子数据双 profile 漂移。演进路径：V1.1+ 若加管理端点再迁表。

`service/TemplateCatalog.java`（final 类 + 私有构造 + `static final List<TemplateInfo>`），内容对齐契约 `TemplateInfo` schema 与原型 `TPL_DATA`，6 条：

| key | category | live | makerPage | festivalDate/festivalLabel |
|---|---|---|---|---|
| LETTER（给妈妈的感恩信） | FESTIVAL | true | `pages/letter-edit/letter-edit` | null |
| DAYS_CARD（相伴天数卡） | COUPLE | true | `pages/days-card-edit/days-card-edit` | null |
| CAPSULE（时光胶囊邀请函） | FUN | true | `pages/capsule-edit/capsule-edit` | null |
| BIRTHDAY_CARD（生日福卡） | FAMILY | true | **null**（live 但无制作页，前端按钮提示「生日当天首页提醒你」） | null |
| HARD_FOR_DAD（给爸爸的一句硬话） | FAMILY | **false**（预约态） | null | 父亲节 2026-06-21 /「父亲节 👔」（日期实现时按万年历复核） |
| WEDDING_CARD（结婚纪念日卡） | COUPLE | **false** | null | null |

previewMeta 每字段照抄原型 `TPL_DATA[key]`（kicker/emoji/sampleText/backgroundKey/sub/feats/usedLabel/durationLabel/恒 `✅ 免费`/hint）。类加载断言：全量 previewMeta 文本过 `DayTextLib.FORBIDDEN_WORDS`、freeLabel 恒「✅ 免费」、live=false 必无 makerPage、枚举 key 与 DTO `TemplateKey` 一致——违者启动失败。

**裁定 ②（节日横幅数据源）**：在 `GET /api/templates` 响应里（`festivalDate`/`festivalLabel` 字段，契约已含），前端横滑节点卡与全部模板网格**同一次请求**驱动，本地算「X 天后」倒计时；服务端不做任何推送调度（FR-5 仅展示层）。

### 1.3 LetterTextLib 降级文案库

`service/LetterTextLib.java`，纯静态无随机，结构满足 D6「每段 ≥2 variants」：

```java
/** 开头 ≥3 写法（OPENING 段 variants 从中取 2 个：默认写法 + 1 备选） */
OPENINGS = { "妈，见字如面。", "亲爱的妈：", "妈，提笔的时候想了很久，" }
/** 每故事 ≥2 写法（STORY 段 variants = 该故事的 2 写法），key=5 个固定素材键（与契约 StoryKey 枚举一致） */
STORY_PARAS = { "她总给我留饭": ["这些年您总给我留饭，热了又热，怕我回来吃凉的。", "每次回家，锅里永远温着我那碗。"], ... }
/** 每语气 ≥2 收尾（CLOSING 段 variants = 该语气 2 写法），key=TEAR/FUN/CALM */
TONE_ENDS = { TEAR: [...×2], FUN: [...×2], CALM: [...×2] }
SIGN_TEXT = "—— 你的孩子"   // 固定落款，不可换
```

组装规则（`assemble(recipient, stories, tone)` → `LetterGenerateResponse`，source=FALLBACK）：段落顺序 = OPENING + 每个请求故事各一段（保序）+ CLOSING，共 2+len(stories) 段（2-7 段）；若请求 stories 为空走校验 40000（契约 minItems=1），不静默兜底。故事段双写法即 variants，selected=第一写法。custom recipient（非「妈妈」）时开头写法里的「妈」字替换为 recipient 文本（简单 `String.replace`，替换后重过违禁词断言）。

类加载断言：每条文本过 `FORBIDDEN_WORDS`、单段 ≤60 字、每个 map 覆盖数达标（开头 ≥3 / 每故事 ≥2 / 每语气 ≥2）——不足即启动失败（合规红线，需求 §5）。

### 1.4 AIService（OpenAI 兼容网关，零第三方 SDK）

`service/AiLetterService.java`，包内可见 `@Service`，构造注入 `ObjectMapper`。

**配置**（环境变量，云托管控制台注入；无 Key 时服务照常启动）：

```
ai.base-url   ← OPENAI_BASE_URL   (默认 https://api.openai.com/v1)
ai.api-key    ← OPENAI_API_KEY     (空 = AI 关闭,全走降级)
ai.model      ← HARNESS_LLM_MODEL  (默认 gpt-4o-mini)
```

**HTTP 客户端**：`java.net.http.HttpClient`（Java 21 内置）单例，`connectTimeout` 2 秒、`requestTimeout`（每请求）10 秒、`FollowRedirects.NEVER`。**不重试**——超时/非 200/IO 异常一律立即降级 FALLBACK（超时预算前端动画层解决，见 §2.5）。日志只打耗时与状态码，**不打请求体**（收信人称呼属用户输入，隐私最小化）。

**prompt 组装**（手写 JSON body，不走 DTO）：

- system：中文家书代笔角色 + 硬约束——输出**严格 JSON**（无 markdown 包裹）、每段 ≤80 字、温暖口语、以「您」称呼收信人、不得出现负面向词汇清单（把 FORBIDDEN_WORDS 直接嵌入 prompt 作负面约束，降低命中概率）。
- user：收信人 + 选中故事（保序）+ 语气（戳泪点/幽默/平淡），要求输出结构：

```json
{"opening": ["写法一", "写法二"],
 "stories": [{"key": "她总给我留饭", "variants": ["写法一", "写法二"]}],
 "closing": ["写法一", "写法二"]}
```

**解析**（`ObjectMapper.readTree` 手写容错）：stories 的 key 必须逐一匹配请求 stories（顺序对齐）；任一层结构缺失/类型错/故事数不符 → **整体解析失败，整封降级 FALLBACK**。解析成功后逐段清洗：每条 variant 过 `DayTextLib.FORBIDDEN_WORDS`（D7 口径，`text.contains(word)` 逐词扫描），**命中即丢弃该条**；段内存活条数 <2 → 用 `LetterTextLib` 对应段写法补齐到 ≥2；某故事段整体缺失 → 降级写法补段。**source 口径：AI 调用成功且结构解析成功即 source=AI**（个别段被过滤补位仍标 AI——source 仅埋点用，用户无感）；AI 关闭/超时/异常/解析失败 → source=FALLBACK。任何路径下 `generateLetter` **不向上抛 AI 相关异常**（需求：信件功能永不因 AI 不可用而报错）。

**频控**（§1.1 表）：方法顺序 = 参数校验（40000 优先，不耗额度）→ `REQUIRES_NEW` 配额自增（>5 抛 40300「今天 5 次写信用完了，明天再来」）→ AI/降级生成。`generationId` = `UUID.randomUUID().toString()`，服务端不存（无草稿态），前端定稿时随 payload 记录。

### 1.5 scene 码签发（POST /api/cards/{id}/share）

- **编码**：`SecureRandom` + base62 字母表（`0-9a-zA-Z`），**固定 8 位**（62⁸ ≈ 2.2×10¹⁴，防枚举）；scene 全库唯一（`share_scene` 唯一索引为真防线）。
- **幂等**：`@Transactional` 内先校验本人+ACTIVE（否则 40400），`shareScene != null` 直接返回既有码——同卡片恒同码；未签发则生成 → `existsByShareScene` 预检 + save，唯一约束兜底，撞码捕获 `DataIntegrityViolationException` 重生成（循环 ≤5 次，实际概率 ~0）。
- **pagePath**：`"pages/visitor/visitor?scene=" + scene`（36 字符，契约 maxLength 需打 32→40 补丁，见 §0）。pagePath 同时是微信好友转发卡片的 path（§2.4）。
- **软删联动**：卡片 DELETED 后 scene 不删（保留追溯），访客端按 scene 查询时过滤 `status=ACTIVE` → 40400。

### 1.6 服务层与事务矩阵（MySQL 严格模式铁律：readOnly 内零写库）

### 1.9 visitor 组安全清单（免鉴权路径专项）

| 威胁 | 对策 |
|---|---|
| scene 枚举/爬取 | 8 位 base62 `SecureRandom`（熵 62⁸）；无效/软删/参数错统一 40400 同文案，无存在性差异（响应体逐字节一致，时序差异不设防——MVP 接受） |
| hearts 刷量（跨设备刷 totalHearts） | deviceId 是客户端生成的，**没有防伪造的强承诺**（需求 D3 明示 device 维度即此语义）；42900 软频控限速（单设备单卡片 >3 次/分钟），内存 `ConcurrentHashMap<deviceId:cardId, Deque<Long>>` 滑动窗口 + 容量上限清理（防内存膨胀）——**裁定 ③：42900 用内存**（软频控、精度要求低，多实例误差可容忍；落库方案在免鉴权高频端点上写放大不划算） |
| PII 泄露 | publicPayload 白名单字段（recipient 文本/relation/天数等），**不含** userId/昵称/手机号/家族信息；photoUrl 仅在解锁后 content 端点下发 |
| 内容门控绕过 | 胶囊未到期：content 端点返回预置悬念文案（真实 contentText 永不进 SEALED 期访客响应）；胶囊本体 SEALED 态无任何访客可读路径暴露 contentText |
| 请求注入 | deviceId 长度 32-64 白名单字符集校验（hex/UUID），scene 正则 `[0-9a-zA-Z]{8,12}`，入库参数化查询（JPA 天然） |

### 2.3 canvas 海报与二维码（**裁定 ④**）

- **画布**：`canvas type="2d"`，设计尺寸 750×1200（rpx 对 1:1，iPhone 主流屏清晰）；三套类样式（信纸夜空 NIGHT/霞橘 SUNSET/薄荷 MINT）复用 app.wxss 渐变令牌，canvas 内以起止色手绘 `createLinearGradient`；品牌位固定底部：左「念家时 + 把重要的日子，记在心上」，右二维码区 200×200rpx。性能预算 ≤3s：正文为定稿纯文本 `fillText` 逐行折行（每 22 字换行），实测路径无网络等待，仅绘制耗时。
- **二维码内容两态**（`utils/cards-data.js` 顶部常量 `QR_LINK_MODE`）：
  - **未发布态（当前，`'path'`）**：QR 内容 = 后端下发的 pagePath 字符串（`pages/visitor/visitor?scene=XXXXXXXX`）。此码**不能**在微信外被识别进小程序（「扫普通二维码进小程序」要求已发布小程序 + 公众平台配置二维码规则）——此态下海报主要服务「保存图片/发朋友圈」的品牌展示与面对面场景的视觉锚点，**病毒主链路走微信好友转发卡片**（`onShareAppMessage` 的 path = pagePath，直达 visitor 页）。
  - **已发布态（`'url'`，运营切换）**：小程序发布后，公众平台「扫普通二维码进入小程序」配置规则：已备案域名 URL 前缀（如 `https://{QR_HOST}/p/`）→ 页面 `pages/visitor/visitor`；前端 QR 内容切换为 `https://{QR_HOST}/p/{scene}`，微信扫普通链接二维码即带参进入小程序（规则把 URL query 透传给页面 `options.q`）。
- visitor 页 `onLoad(options)` 双入口解析：`options.scene`（转发卡片/页面路径直达）与 `options.q`（普通二维码，`decodeURIComponent` 后正则提取 scene）。
- QR 生成用 vendored 纯 JS 单文件模块（§2.1 utils/qrcode.js），**不引 npm、不手写纠错编码**（Reed-Solomon 手写风险高）；后端零出图（决策 D2）。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 契约 `pagePath maxLength:32` 与实际 36 字符矛盾，Stage 4 codegen/校验必炸 | §0 已裁定 scene 固定 8 位 + 契约补丁 maxLength 32→40（spec JSON 同步），进 Stage 3 评审结论强制执行 |
