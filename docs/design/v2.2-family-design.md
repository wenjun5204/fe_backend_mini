### 1.3 PhotoService（上传 / 回图 / GC）

**POST /api/photos（upload）**，校验顺序即实现顺序（40000 优先于 40300，先廉价的先做）：

1. `scene` 枚举校验（MOMENT/CAPSULE），否则 40000「照片用途不对，请重新选择」。
2. **解前先验长度**：`imageBase64` 为 null/空白 → 40000；`str.length() > 700_000`（512000×4/3≈682,668 + Base64 padding 余量）→ 40000「照片太大，请压缩后再传」——**不解码超大载荷**（防 base64 解码放大 DoS）。
3. `Base64.getDecoder().decode()`，`IllegalArgumentException` → 40000「照片数据损坏，请重试」；解码后 `length ∈ [1, 512000]` 否则 40000。
4. mime 判定：**始终嗅探字节头**——`FF D8 FF`=jpeg、`89 50 4E 47`=png、`RIFF…WEBP`(offset 8)=webp；嗅不出 → 40000「只支持 jpg、png、webp 照片」。请求带 `mimeType` 时须属枚举**且与嗅探结果一致**（不符 40000，防 Content-Type 撒谎）；缺省用嗅探值。
5. 频控：`countByUserIdAndCreatedAtGreaterThanEqual(userId, 今日零点) >= 20` → 40300「今天传了 20 张照片，明天再来」。
6. photoId 生成：`SecureRandom` + base62（复用 CardService 的字母表常量，抽到公共处或各自持有）固定 18 位；`existsByPhotoId` 预检 + 唯一索引兜底重生成（循环 ≤5，实际概率 ~0，同 §1.5 scene 签发模式）。
7. 落库 status=ORPHAN；响应 `{photoId, photoUrl:"/api/photos/"+photoId, sizeBytes}`。

**GET /api/photos/{photoId}（回图，免鉴权）**：photoId 正则 `[0-9a-zA-Z]{16,20}` 预校验；查行，`status=DELETED` 或不存在 → 40400「没有找到这张照片」（同文案，不泄露存在性）；ORPHAN（48h 内未绑定）与 ACTIVE 均**正常回图**——上传响应的 photoUrl 供发布前预览。返回 `ResponseEntity<byte[]>`：`Content-Type: image/{jpeg|png|webp}`、`Cache-Control: public, max-age=2592000`（30 天；photoId 内容不可变，同 id 恒同图）、附加 `X-Content-Type-Options: nosniff`（capability URL 直挂 `<image>`，杜绝内容嗅探歧义）。本端点走统一错误通道（`ApiErrorHandler` HTTP 200 + `{code,message}` JSON），`<image>` 收到 JSON 即裂图占位，行为可接受（与 visitor 组同口径）。

**ORPHAN GC**：`PhotoService` 内 `@Scheduled(fixedDelay = 3600_000)` 方法，`deleteByStatusAndCreatedAtBefore(ORPHAN, now-48h)`。需在 `BackendApplication` 加 `@EnableScheduling`（工程首次引入调度，无既有冲突）。多实例并发扫除幂等（delete where 条件恒定，重复执行零行）。GC 物理删行 → 回图自然 40400，与契约「ORPHAN 超时回收后 40400」一致。

### 1.4 MomentService（瞬间 / 真好 / 收藏 / 素材池）

身份取 `CurrentUser.get()`；家族取 `familyMemberRepository.findByUserId`（**瞬间全线要求家族**，与 days 的「无家族不拦截」相反——家人空间以家族为界）。

**发布（POST /api/moments）**：未加入家族 → 40900「先创建或加入一个家，再记录家人瞬间」；`photoId` 查行须 **本人上传 + scene=MOMENT + status=ORPHAN**（他人照片/scene 不符/已绑定 → 40000「这张照片不能用，请重新选择」）；`text` trim 后 1-60 字 + 过 `DayTextLib.FORBIDDEN_WORDS`（命中 40000「这句话里有不合适的词，麻烦改一改」）；频控 `countByUserIdAndCreatedAtGreaterThanEqual >= 10` → 40300「今天发了 10 条瞬间，明天再记录」；同事务内：落 moment（familyId 快照）+ 照片 ORPHAN→ACTIVE、写 moment_id。响应 FamilyMomentView（likeCount=0/likedByMe=false/collectedCount=0/collectedByMeDayIds=[]）。

**时间线（GET /api/moments）**：无家族 → 空数组（契约：不报错，前端空状态）；`limit` 缺省 10，越界（<1 或 >20）→ 40000；`beforeId` 缺省视为 0；查 `findByFamilyIdAndStatusAndIdLessThanOrderByIdDesc` 取 limit+1 条判 `nextCursor`（还有更早才下发，否则缺省）。每页 ≤20 条，计数/互动态**批量查询**防 N+1：likeCount/collectedCount 各一条 group by、likedByMe/collectedByMeDayIds 按 userId+momentIds 各一条——4 条附加查询撑满整页。`photoUrl` 恒 `/api/photos/{photoId}`；**发布人昵称不下发**（契约：前端经 `GET /api/family` 成员列表解析 userId→昵称）。

**删除（DELETE /api/moments/{id}）**：行不存在 → 40400；`moment.userId != 当前用户` → 40400（**户主/家人均不可删他人——隐私权红线，校验只认 userId，不认角色**）；status 已 DELETED 且本人 → 幂等返回 `{deleted:true}`。软删 + 同事务联动照片置 DELETED（回图 40400）；moment_like/moment_collect 行**保留**（历史计数与已存档福卡 payload 不追溯——契约「素材瞬间后续被删不影响已存档 payload」）。moment_collect 行保留但素材池查询 join moment 过滤 ACTIVE，条目即时消失。

**真好（POST/DELETE /api/moments/{id}/like）**：moment 须存在且 ACTIVE 且**属本家族**（跨家族/不存在 → 40400 同文案）；POST upsert（`uk(moment_id,user_id)` 兜底并发，重复调用幂等不增数）；DELETE 删行幂等。两者响应 `MomentLikeResponse{likeCount(操作后计数), likedByMe(POST 恒 true / DELETE 恒 false)}`。

**收藏进日子（POST /api/moments/{id}/collect）**：moment 属本家族 ACTIVE（否则 40400）；`dayId` 必填（缺 → 40000）；目标 DayRecord **本人可见**（`canView`：本人创建 OR 同家族 FAMILY）——不可见/不存在 → 40400「没有找到这条日子」；`kind != BIRTHDAY` → 40000「生日福卡的素材，要收藏到生日日子里」；upsert `uk(moment_id, day_id, user_id)` 幂等。DELETE（query `dayId`）：dayId 缺失/非法 → 40000；同样过 moment 可见校验（40400）后删行，幂等。响应 `MomentCollectResponse{collectedCount, collectedByMe, dayId}`。

**素材池（GET /api/days/{id}/moments）**：DayRecord 本人可见（否则 40400）+ `kind=BIRTHDAY`（否则 40000）；`findByDayIdOrderByIdDesc` 逐行加载 moment 过滤 ACTIVE，组装 `DayCollectedMomentItem{momentId, photoUrl, text, authorName(发布人昵称, UserRepository 查), collectedBy(收藏人昵称), collectedAt}`；空数组触发前端空状态。此端点**服务端解析昵称**（与时间线的 userId-only 口径不同，契约各异，按契约实现）。

### 1.5 FestivalService（预约 / 到期）

`TemplateCatalog` 的 festivalDate 字段既有（`TemplateInfo` 已含），本 change 的数据扩展：**LETTER 补「母亲节」节点日期**（2027-05-09，5 月第二个周日，实现时按万年历复核），HARD_FOR_DAD 的父亲节日期随版本滚动更新（2027-06-20，6 月第三个周日；当前 2026-06-21 已过期自然出窗）。festivalDate 是静态字符串随版本管理（TemplateCatalog 静态类的既定模式），到期后由运营在下个版本更新——MVP 接受。

- **POST /api/festivals/reservations**：templateKey 必须 ∈ TemplateKey 枚举且在 TemplateCatalog 有配置（否则 40400「没有找到这个模板」）；upsert `uk(user_id, template_key)`——已存在直接回读（reservedAt 首次时间不变），并发撞唯一约束捕获 `DataIntegrityViolationException` 回读。响应 `{templateKey, reserved:true, reservedAt}`。
- **GET /api/festivals/reservations**：`findByUserIdOrderByCreatedAtDesc` 逐行 join TemplateCatalog 组装 `{templateKey, name, live, festivalLabel, festivalDate, daysUntil(按 festivalDate 算，非节日为 null), reservedAt}`。
- **DELETE /api/festivals/reservations/{templateKey}**：templateKey 非 TemplateKey 枚举值 → 40000；删行（无行也成功），恒 `{deleted:true}`。
- **GET /api/festivals/due**：`date` 可选（yyyy-MM-dd，解析失败 40000；缺省今天）；遍历 `TemplateCatalog.list()` 取 festivalDate 非空项，`daysUntil = DAYS.between(basis, festivalDate)`，保留 `[0,7]` 窗口；`reservedByMe = findByUserIdAndTemplateKey 存在`；`dueSoon = reservedByMe && daysUntil <= 3`；按 daysUntil 升序。`emoji` 字段从 festivalLabel 提取（正则拆出非中文段，如「父亲节 👔」→「👔」，无则 null）。**无任何 subscribeMessage.send 调用**（验收红线）；预约与 `NotifyService` 的关系 = 两条平行账：reservation 记「想被提醒什么」，`/api/notify/subscribe` 记「授权了几条推送额度」——真实下发（reservations × dueSoon 扫描 → subscribeMessage.send，扣 NotifyService 4 条/日额度）属部署联调阶段 Stage 9，本 change 交付的 due/reservations 数据即其输入。前端预约动作顺手调 `wx.requestSubscribeMessage` + `/api/notify/subscribe`（静默降级，同 capsule-edit 既有模式，§2.4）。

### 1.6 DayService 扩展（year）与 AnniversaryTitleLib

**`DayDtos`**：`DayUpsertRequest` + `Integer year`；`DayRecord` + `Integer year / Integer anniversaryNumber / String anniversaryTitle / String anniversaryLabel`（全包装类型，nullable）。

**校验（applyRequest 内，全 kind 统一）**：`year == null` 放行；`year < 1900 || year > LocalDate.now().getYear()` → 40000「年份要在 1900 年到现在之间」。TOGETHER 且 year 非空时 `LocalDate.of(year, month, day)` 须真实存在（2 月 29 配平年 → 40000「请您换个日期」）——否则读取期 `togetherStart` 构造 LocalDate 会炸历史行。PUT 全量覆盖：`record.setYear(request.getYear())`（不传即清空，契约「全量覆盖，改后周年字段即时重算」）。

**计算字段（toDto，按 kind 分支）**：

| kind | year 语义 | 计算 |
|---|---|---|
| ANNIVERSARY | 称谓计算基数 | `nextDate`（既有换算）非空且 year 非空 → `N = nextDate.getYear() - year`；`anniversaryNumber=N`、`anniversaryTitle=AnniversaryTitleLib.title(N)`（未收录为 null）、`anniversaryLabel=N + " 周年"`；year 缺省 → 三字段 null。倒计时「距 N 周年还有 X 天」由前端组合 daysUntil |
| TOGETHER | 补录起始年（Change 1 D1 兑现） | `togetherStart(record)` 改为：year 非空 → `LocalDate.of(year, month, day)`；缺省仍 `createdAt 年 + month/day`（既有数据兼容）；togetherDays 公式不变 `max(1, between(start, today))`。不输出称谓 |

### 1.9 Controller、DTO 与 springdoc（含二进制端点）

`ApiController` 新增 14 路由（类头注释 46→60），薄委托一行。**springdoc 教训（硬要求）**：每个端点 `@ApiResponses` 含 200 + 契约声明的全部 4xx，responseCode 与契约 responses 键一一对应——如 POST /api/photos = 200/400/401/**403**；POST /api/moments = 200/400/401/403/**409**；GET /api/photos/{photoId} = 200/**404**（免鉴权组，无 401）。

**二进制回图端点的注解写法（不破坏 api-docs）**：`public ResponseEntity<byte[]> getPhoto(@PathVariable String photoId)`，200 的注解声明 `@Content(mediaType = "image/jpeg", schema = @Schema(type = "string", format = "binary"))`（契约 200 的三种 image/* 里取主形态 jpeg；png/webp 属同一 binary 语义，不逐 mediaType 展开），404 照常 `ErrorDtos.ErrorResponse`。springdoc 对 `ResponseEntity<byte[]>` 返回类型自动按 binary 推断，注解只保证 responses 键齐全；Cache-Control 契约 headers 不在注解层声明（非 schema 元素，运行时头为准）。运行时动态：`ContentType` 取实体 mime 列（`MediaType.parseMediaType`），不硬编码。**错误仍走统一 HTTP 200 + `{code,message}` 通道**（`ApiErrorHandler` 既有模式，与 @ApiResponses 的 4xx 声明并存是本 harness 既定约定——注解对齐 api-docs 契约比对，运行时走 body.code）。

`WebConfig.excludePathPatterns` 追加 `"/api/photos/*"`——Ant 风格 `*` 匹配单段：放行 `/api/photos/{photoId}`（GET 回图免鉴权），**不放行 `/api/photos` 本身**（POST 上传仍鉴权）。集成测试双向断言（§3）。

DTO：新建 `PhotoDtos.java`（PhotoScene/PhotoMimeType/PhotoUploadRequest/PhotoUploadResponse）、`MomentDtos.java`（MomentCreateRequest/FamilyMomentView/MomentListResponse/MomentLikeResponse/MomentCollectRequest/MomentCollectResponse/DeleteMomentResponse/DayCollectedMomentItem/DayCollectedMomentsResponse）、`FestivalDtos.java`（FestivalReservationRequest/FestivalReservation/ReservationListItem/ReservationListResponse/CancelReservationResponse/FestivalDueItem/FestivalDueResponse）。改 `DayDtos`（+year 四字段）、`CardDtos`（CardKind+CardPayload 四字段）、`CapsuleDtos`（CapsuleCreateRequest/TimeCapsule +photoId）、`VisitorDtos`（VisitorPublicPayload/HiddenContent +BIRTHDAY_CARD 字段）。契约 codegen 骨架仅作字段核对清单，人工 DTO 为唯一交付物（v2.0 §1.6 同路径）。

`utils/photo.js` 的 `chooseAndUpload(scene)`：

1. `wx.chooseMedia({count:1, mediaType:['image']})` 单张（隐私最小化红线：**不批量读相册**）。
2. 压缩循环：`wx.compressImage({src, quality})` 从 80 起，`FileSystemManager.getFileInfo` 查大小，>500KB 则 quality −20 递降到 20；仍超（原图即极端小图之外）→ toast「这张照片太大，换一张试试」中止。目标 ≤480KB 留余量（服务端 512000 硬闸）。
3. `FileSystemManager.readFile({filePath, encoding:'base64'})` → `POST /api/photos` `{imageBase64, scene, mimeType}`（普通 JSON 请求，request() 双通道零改动——base64 协议的选型红利）。
4. 返回 `{photoId, photoUrl}`；调用方持有 photoId 到后续绑定（moments POST / capsules POST）。

**photoUrl 绝对地址解析（`absPhotoUrl`）**：契约 photoUrl 恒相对路径 `/api/photos/{photoId}`，`<image src>` 需绝对地址——`USE_CLOUD ? CLOUD_PHOTO_BASE + path : BASE_URL + path`。本地通道 BASE_URL 已有；云通道 `CLOUD_PHOTO_BASE` 为云托管服务的公网访问域名常量（与 `SERVICE_NAME` 同处维护，部署后填入）。**部署 checklist**：该域名须在小程序后台配置为 request 合法域名（`<image>` 直挂与 `wx.getImageInfo` 海报绘制均走它）；开发者工具阶段勾选「不校验合法域名」即可联调。

DELETE : POST（乐观更新 + 失败回滚，同 day-detail 提醒开关模式）；⭐ 点按弹 BIRTHDAY 日子选择 actionSheet（本地缓存 `GET /api/days` 过滤 kind=BIRTHDAY 且本人可见——服务端 40400 兜底）→ POST collect（collectedByMeDayIds 增补驱动已收藏态/取消）；删除 = `wx.showModal` 二次确认（文案「删掉后家人也看不见了」）→ DELETE → 本页移除。

## 4. 风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R1 | 云托管 callContainer 网关请求体上限（约 1MB 或更小）vs 500KB 照片 base64 后 ~680KB——Stage 2 checkpoint 未验证 | 前端压缩循环目标 ≤480KB（余量）；联调实测网关；若不达标：压更狠（quality 下探/分辨率裁切）或回退 multipart（契约 requestBody 编码层留了回退口径，不改 schema） |
| R2 | 契约两处残留文本（CardPayload.dayId 的 40900 门控、makerPage 括注）与裁定修订矛盾，Stage 4 codegen/校验可能误读 | §0.1 勘误清单进 Stage 3 评审结论强制执行（只改 description 文本，schema 结构零变化） |
| R3 | `<image>`/canvas 直挂照片需云托管公网域名进小程序合法域名白名单（request + downloadFile），漏配则上线灰图 | §2.3 absPhotoUrl + 部署 checklist（域名常量 CLOUD_PHOTO_BASE 与白名单同步配置）；开发者工具「不校验合法域名」本地先行 |
| R4 | MySQL BLOB 列宽踩坑：裸 byte[] 映射 VARBINARY(255) 会在线上报「Data too long」 | §1.1 已查证并锁定 `@Lob byte[]`（H2 blob / MySQL longblob，Hibernate 7.4.5 字节码实证）；集成测试虽在 H2，上云前用云 profile 冒烟一次 500KB 落库 |
| R5 | 瞬间素材池/时间线的昵称解析与计数 join 在家族增大后查询放大 | 时间线每页固定 4 条批量聚合查询（无 N+1）；素材池无分页但家族级数据量（几十行）走「全量拉取 + 内存组装」既有策略；V2 加分页时契约 cursor 形态已就位 |
