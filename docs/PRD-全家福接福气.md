## 1. 产品概述

### 1.1 一句话定位

> **每天为全家抽一张福卡，做点小事攒福气，全家人一起把福值抬上家族榜。**

### 1.2 设计哲学：心理引擎驱动，功能只是载体

前序方案（健康打卡互助团）的根本问题：**健康是中老年的焦虑，不是快乐**。焦虑产品留得住人但传不开；转发传播需要的是快乐、惦记和面子。

本方案把产品骨架（家庭组队、每日微任务、催一下、排行榜）全部保留，但心理引擎全换：

| 引擎 | 心理机制 | 本方案对应设计 |
|---|---|---|
| 祈福求安（主引擎） | 家人平安 > 一切，为家人做事心甘情愿 | 每日福卡：抽的不是自己的签，是**全家的平安** |
| 同辈攀比（裂变引擎） | 家族与家族之间的面子战 | 家族福值榜 + 「满门福气」门牌 |
| 被子女需要 | 怕成为负担，渴望价值感 | 子女给父母「添福」，父母给孙辈「送平安」 |
| 怕死但不锻炼（暗线） | 健康焦虑强、行动力弱 | 微任务藏在福卡里，完成任务的回报是"明天福卡更旺" |

**核心区别**：健康打卡问用户"你今天做没做"（质问感）；福卡对用户说"你为家人积福了"（授予感）。

### 1.3 要解决的问题

| 用户侧痛点 | 方案 |
|---|---|
| 想为家人祈福但没有仪式载体 | 每日福卡：摇一摇、金光、翻卡，动作有肌肉记忆 |
| 转发早安图没新意，显得老土 | 福卡是精美动态卡片，转出去"有面子" |
| 健康任务坚持不了 | 任务降级为"福卡附赠"：不做不扣福，做了多攒福 |
| 家族群没有共同活动 | 家族福值池：全家人的行为汇成一件事 |
| 容易忘记长辈生日，想关心却总是错过日子 | 家庭生日簿：一次录入生日，自动展示农历日期并在重要日子提醒家人 |

### 1.4 北极星指标

**每日「福卡激活」家庭数（Daily Blessed Families, DBF）**

定义：当日至少 2 名家庭成员完成抽卡并转发的家庭数。它同时衡量留存（家人回访）与传播（转发动作）。

## 2. 目标用户（沿用前序画像，行为假设更新）

- **王阿姨（58，核心用户）**：从前一天发 3 张早安图；现在发 1 张福卡——更精美、带全家名字、还能看福值。转发理由从"维护关系"升级为"为家人求平安"。
- **小刘（31，付费+拉新用户）**：以前打电话尬聊；现在每天给妈妈的福卡「添福」一次（免费动作，情感价值极高），节日买「全家福修复」孝心付费。
- **老陈（63，攀比传播用户）**：看到老王家门牌"满门福气"不服 → 拉自己全家进榜 → 他的子女也被拉进来。

## 3. 核心机制设计

### 3.1 福值体系（统一货币）

| 行为 | 福值 | 说明 |
|---|---|---|
| 每日抽福卡 | +5 | 上限 1 次/天 |
| 福卡转发到家人群（激活） | +10 | 核心行为，转发即激活 |
| 完成福卡附赠微任务 | +15 | 如"多喝两杯水"、"散步 20 分钟" |
| 家人给你「添福」 | +8/次 | 每人每天可给每位家人添福 1 次 |
| 连续 7 天全家抽卡 | 家族福池 +50 | 团队性激励 |
| 邀请一位家人入「家」 | +30 | 裂变激励 |

**规则**：
- 福值分两层：**个人福值**（攒福禄，兑换个人头像挂件）+ **家族福池**（全家人福值自动汇入，决定家族榜排名）
- 福值只涨不跌，**永不惩罚**（中老年用户被扣分 = 卸载）
- 榜单以"家族"为单位，家族名 = "王家庄""刘家大院"（默认生成，可改）

### 3.2 每日福卡（核心仪式）

**流程**：

```
推送「今天的福卡到了」(7:30)
  → 打开小程序，中央一支金色签筒
  → 摇一摇手机（或点按钮）→ 签筒晃动 → 一道金光
  → 翻出福卡：「平安卡 · 今日宜多喝水，家人无恙」
  → 卡片底部一行小字：「转发到家人群，为全家激活」
  → 转发 → 卡片点亮金边 → "全家福卡已生效 +10 福值"
```

**福卡设计规范**：
- 每天 1 张，全家族抽到的是**同一张**（"咱们家今天的福卡"——归属感）
- 卡面：国风插画（锦鲤/寿桃/福字/平安锁），日期 + 家族名，**必须有"王家庄 全家"字样**（专属感）
- 福卡等级：平安卡（70%）→ 如意卡（25%）→ 鸿福卡（5%）——稀有度刺激晒卡
- 等级只影响卡面华丽程度和附赠微任务数量（如意卡 2 个任务），**不影响福值倍率**（避免"抽不到好卡"的挫败）
- 微任务从生活化任务库随机：多喝水 / 散步 20 分钟 / 早睡 / 给家人打个电话 / 泡脚
- **合规红线（见 §7）**：福卡文案只做"祝福"，绝不做"预测"。禁用：运势、吉凶、求签、算命、改运、挡灾。卡面永远是正面祝福语。

### 3.3 「添福」互动（替代原「点个赞」，情感浓度升级）

- 团主页每位家人头像旁有「添福」按钮（金色小葫芦图标）
- 点击 → 对方收到订阅消息：「儿子给您添福啦！全家福值 +8」
- 每天给每位家人限 1 次（稀缺才珍贵，泛滥就变成点赞）
- **「给家人打个电话」本身是微任务**：福值体系鼓励真实联系，这是产品的道德底色

### 3.4 「催福」提醒（替代原「催一下」，语气重设计）

- 家人今日未抽卡 → 团主页显示"还没接福"
- 「催福」按钮 → 对方收到：「王阿姨请您接今日福卡，全家人就等您啦！」
- 文案库核心原则：**全家在等您**（归属感召唤），不是"您偷懒了"（批评）
- 每人每天对同一位家人限 3 次

### 3.5 家族福值榜（攀比引擎，传播主战场）

**三层榜**：

| 榜 | 范围 | 内容 |
|---|---|---|
| 家内榜 | 本家成员 | 本周谁为家里攒福最多（家庭内部攀比，安全） |
| 好友家族榜 | 微信好友的家族 | "老王家 890 · 老李家 720"（家族对家族） |
| 同城家族榜（V1.1） | 同城/同县 | 「岳阳县福值榜第 3 名」——地域认同感爆炸 |

**排名文案示例**：
- 落后时："就差 120 福值追上老李家了，今天全家抽卡就能反超！"
- 领先时："稳住！老李家本周奋起直追中"（制造假想敌）

**门牌体系（核心炫耀物）**：

| 家族累计福值 | 解锁 |
|---|---|
| 500 | 青铜门牌「勤俭之家」 |
| 2000 | 白银门牌「和睦之家」 |
| 5000 | 金字门牌「满门福气」 |
| 20000 | 玉匾「福泽满堂」 |

- 门牌 = 家族群头衔的视觉化，设计成**可以直接设为群头像**的正方形图
- 每次升级门牌 → 全家收到通知 → 门牌分享卡自带小程序码 → **榜外家族扫码进入**（裂变闭环）

### 3.6 节气/节日大事件（传播爆点日历）

| 时点 | 玩法 |
|---|---|
| 每逢节气 | 限定福卡（立冬"添衣卡"、冬至"团圆卡"），卡面更华丽 |
| 春节 | 「全家集五福」：福/禄/寿/喜/财五张卡，**全家分工集齐才有大奖门牌**（强拉新） |
| 重阳 | 「敬老福」：子女给父母添福 9 次，解锁专属"长寿面"动效卡片 |
| 家人生日 | 当日福卡可出现「生日祝福版」卡面；不改变抽卡概率、福值或榜单规则 |

### 3.7 家庭生日簿（v1.3：农历日期转换 + 关怀提醒）

#### 3.7.1 功能定位与边界

> **帮您记住家人的生日，并把公历日期换算成农历日期，让每一次惦记都不迟到。**

这是家庭关怀工具，不是每日任务或福值玩法：

- 只提供公历日期与农历日期的**确定性日历换算**、生日保存和提醒；
- 不根据日期给出任何解释、评价、标签或未来相关内容；
- 不展示或收集出生时刻、出生地点等非必要信息；
- 不与福值、门牌、榜单或任何实物奖励挂钩；不要求分享、邀请或付费；
- 用户不保存时仅做本次计算，退出页面后不留存该日期。

#### 3.7.2 用户角色与价值

| 用户 | 典型情境 | 产品价值 |
|---|---|---|
| 长辈 | 记不清孙辈或远方子女的农历生日 | 打开生日簿即可查看，不用翻纸质日历 |
| 子女 | 工作忙，常在生日当天才想起给父母问候 | 提前 7 天、3 天收到提醒，留出准备礼物和联系的时间 |
| 户主 | 想让全家记住长辈的重要日子 | 统一维护家庭生日簿，减少家族群反复询问 |

#### 3.7.3 核心流程

```text
我的家 → 家庭生日簿 → 点击「记一位家人的生日」
  → 填写称呼/姓名，选择公历或农历的月、日
  → 即时展示下一次生日对应的农历/公历日期
  → 用户选择「只我可见」或「家人可见」
  → 确认保存
  → 生日簿按下一次生日由近到远排列

仅查询（不保存）
  → 输入完整公历日期 → 即时展示该日期对应的农历日期
  → 退出页面即清除本次查询内容

生日临近（提前 7 天 / 3 天 / 当天）
  → 已授权提醒的家人收到一次提醒
  → 打开小程序查看寿星、日期和「送一句祝福」入口
  → 选择预置祝福后复制，或由用户主动发起分享
```

**录入规则**：

1. 保存生日时默认按公历选择月、日；页面实时展示下一次生日对应的农历日期，供用户核对；
2. 对只知道农历生日的家庭，提供「按农历记生日」切换，需选择月份、日期及是否闰月；
3. 保存时仅记录用户选择的月、日、日期口径和闰月标记（如有），后续每年均按该口径计算下一次生日；
4. 「只查不保存」模式可选择 1900-01-01 至当天的完整公历日期，展示该日期的农历对应日期；拒绝未来日期和无效日期；
5. 每个家庭成员最多保存 1 条生日记录；若录入亲友（非小程序成员），须填写称呼或姓名，最多保存 20 位；
6. **保存生日不采集出生年份、出生时刻或出生地点**；不提供年龄计算或展示。

#### 3.7.4 页面与交互设计

| 页面/区域 | 内容 | 关键交互与适老化要求 |
|---|---|---|
| 我的家：生日簿入口 | 「近期生日」卡片，展示最近一位家人的称呼、距生日天数和农历/公历日期 | 无近期记录时展示「记下家人的生日」；入口与主操作同屏，点击后 ≤ 2 步到添加页 |
| 生日簿列表 | 按下一次生日升序展示；每项含称呼、日期口径、农历与公历对照 | 一屏只突出最近一位；其余用列表，避免密集信息 |
| 添加/编辑页 | 称呼或姓名、日期选择器、日期口径、可见范围、提醒开关 | 必填信息分组呈现；选择日期后立即给出大字农历结果；不需要填写年份；保存按钮高度 ≥ 88rpx |
| 生日关怀页 | 「今天是妈妈的生日」+ 日期 + 3 条预置祝福 | 可一键复制或由用户主动转发；没有“转发后解锁”逻辑 |

**预置祝福示例**：

- 「祝您生日快乐，天天都有好心情。」
- 「愿您吃得香、睡得甜，和家人常相见。」
- 「今天想您啦，祝您生日快乐！」

所有祝福均为日常关怀文案，不包含任何推断、健康疗效或承诺。

#### 3.7.5 数据、权限与生命周期

| 数据项 | 是否必填 | 用途 | 可见范围/保存规则 |
|---|---:|---|---|
| 称呼或姓名 | 是 | 在生日簿和提醒中识别对象 | 仅保存于所属家庭；用户选「只我可见」时仅本人可见 |
| 生日月、日 | 是 | 下一次生日计算、农历/公历对照与提醒 | 同上；用户可随时编辑或删除 |
| 日期口径（公历/农历、闰月标记） | 是 | 计算每年的对应日期 | 同上 |
| 完整查询日期 | 否 | 仅用于本次农历日期换算 | 不保存、不写日志，退出页面即清除 |
| 提醒接收人及开关 | 否 | 向用户主动选中的家人发送生日提醒 | 可随时关闭；关闭后不再发送 |

- 初次保存前需用明确文案告知：「生日信息只用于日期换算和提醒，您可随时删除。」
- 删除生日记录后，服务端立即删除对应日期及提醒配置；不保留历史提醒内容。
- 不以生日信息做画像、广告定向、榜单排序或任何自动化推断。
- 小程序隐私保护指引需在上线前新增“生日信息”处理说明，写明用途、保存范围、删除路径及联系渠道。

#### 3.7.6 提醒策略与频控

| 触发时点 | 默认状态 | 接收人 | 文案示例 | 限制 |
|---|---|---|---|---|
| 提前 7 天 | 关闭 | 用户主动选择的家人 | 「下周是妈妈的生日，记得给她打个电话。」 | 同一生日仅 1 次 |
| 提前 3 天 | 关闭，用户主动开启 | 用户主动选择的家人 | 「妈妈生日快到了，想想怎么陪她过吧。」 | 同一生日仅 1 次 |
| 当天 9:00 | 关闭，用户主动开启 | 用户主动选择的家人 | 「今天是妈妈的生日，送一句祝福吧。」 | 同一生日仅 1 次 |

- 初次开启任一时点时，先说明提醒内容并请求对应订阅消息授权；未授权或拒绝授权时保持关闭。
- 所有生日提醒纳入全局订阅消息总量控制：每人每日最多 4 条；超限时按优先级延后，不补发过期提醒。
- 未获得订阅消息授权时，只在用户主动打开小程序后展示站内提醒，不以其他方式打扰。
- 生日提醒只提供关怀信息，不附加福值、奖励、任务、商品或外部推广链接。

#### 3.7.7 规则与异常处理

| 场景 | 处理规则 |
|---|---|
| 当年农历无对应日期 | 采用当地通行日历规则映射至当月最后一天，并在列表标记「按当年日历计算」 |
| 闰月生日 | 用户保存时必须明确是否为闰月；未选择则按非闰月计算 |
| 日期换算服务不可用 | 展示「暂时无法换算，请稍后再试」；不保存未确认结果，不以猜测日期替代 |
| 家庭成员退出家庭 | 保留其生日记录仅供录入人查看；户主可删除家庭共享记录 |
| 多人编辑同一成员生日 | 采用最后一次确认保存的版本，并记录最近修改人和时间供户主查看 |
| 用户关闭提醒 | 立即停用该用户对应生日的所有未来提醒，不影响其他已选择的家人 |

#### 3.7.8 数据模型与接口范围（开发前先更新 OpenAPI 契约）

**核心对象：BirthdayRecord**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | integer | 是 | 记录 ID |
| familyId | integer | 是 | 所属家族 ID |
| subjectType | enum | 是 | `MEMBER`（家族成员）或 `CONTACT`（亲友） |
| subjectUserId | integer | 条件必填 | `MEMBER` 时必填，且必须属于该家族 |
| displayName | string | 是 | 成员昵称或亲友称呼，长度 1-12 |
| calendarType | enum | 是 | `SOLAR`（公历）/ `LUNAR`（农历） |
| month / day | integer | 是 | 生日月、日；按日期口径校验合法范围 |
| isLeapMonth | boolean | 是 | 农历生日是否为闰月；公历固定为 false |
| visibility | enum | 是 | `PRIVATE`（仅录入人）/ `FAMILY`（家人可见） |
| createdBy | integer | 是 | 录入人 ID |
| reminderEnabled | boolean | 是 | 当前用户是否接收提醒；提醒接收人单独建关联表 |
| nextBirthdayDate | string | 是 | 服务端按当年日历计算出的下一次生日（仅展示用） |
| nextBirthdayLunarText | string | 是 | 下一次生日的农历显示文本（仅展示用） |

**新增接口（路径为建议，开发前以 OpenAPI 为准）**：

| 方法 | 路径 | 说明 | 鉴权/校验 |
|---|---|---|---|
| `POST` | `/api/calendar/convert` | 临时公历/农历日期换算 | 只返回结果，不落库，不记录完整查询日期 |
| `GET` | `/api/birthdays` | 获取本人可见的家庭生日簿及近期生日 | 按 `visibility` 与家族归属过滤 |
| `POST` | `/api/birthdays` | 新增一条生日记录 | 校验称呼、日期、成员归属、家庭记录上限 |
| `PUT` | `/api/birthdays/{id}` | 编辑日期、称呼、可见范围 | 仅录入人或户主可编辑家庭共享记录 |
| `DELETE` | `/api/birthdays/{id}` | 删除生日记录与关联提醒 | 立即停止未来提醒 |
| `PUT` | `/api/birthdays/{id}/reminder` | 设置当前用户的提醒开关和时点 | 必须已有订阅消息授权才可开启 |
| `GET` | `/api/birthdays/upcoming` | 获取近期生日，供“我的家”卡片使用 | 仅返回用户有权查看的最小字段 |

#### 3.7.9 非功能与技术要求

- 农历换算使用经过测试的日历算法或服务，并覆盖 1900-2100 年；服务端作为唯一计算来源，前端只展示结果；
- 日期换算结果需提供单元测试样本（普通月份、春节附近、闰月、年末边界）；
- 生日数据接口仅允许本人、所属家庭内获授权成员访问；服务端必须做家族归属校验；
- 删除、提醒开关和可见范围变更均须可审计；日志不得记录完整查询日期或完整生日日期；
- 生日簿首屏接口 P95 ≤ 500ms；日期换算操作 P95 ≤ 800ms；失败需有明确且口语化的提示。

#### 3.7.10 验收标准

1. 用户选择任一有效公历日期后，页面在 1 秒内展示对应农历日期；保存后重新打开结果一致；
2. 用户不保存时，刷新或退出后生日簿中不存在该记录；
3. 「只我可见」记录不出现在其他家庭成员的生日簿、提醒或接口响应中；
4. 用户删除记录后，该记录不再展示，且未来提醒不再触发；
5. 用户主动开启提醒并完成订阅授权后，所选时点每年最多收到一次提醒；任一用户全天提醒总量不超过 4 条；
6. 所有生日相关页面、接口字段、订阅模板和分享文案均不包含推断、预测或医疗暗示；
7. “送一句祝福”可不分享直接完成，分享仅由用户主动发起，页面不提供因分享获得额外权益的逻辑。

### 3.8 八卦集福阵（v1.4：家庭成就总骨架）

#### 3.8.1 功能定位

> **全家人的一张东方美学进度盘：八方卦位对应八类家庭善行，点亮卦位、集满成阵。**

八卦阵是本产品的成就总骨架与家庭状态仪表盘，不是占卜工具。它把现有散装功能（福卡、微任务、添福、裂变）统一进一张可视化的「家的全息图」：

- 卦位是**成就系统的皮肤**，只表达「已完成 / 未完成」与进度，不表达吉凶；
- 阵图中央动态展示家庭当前状态（全家福照片，或最近的大日子，依赖倒数日能力上线）；
- 八卦圆满是全产品最高规格的**全家共同成就**与核心传播物。

- **触发条件**：八个卦位全部点亮（震卦首次点亮即计入）；

1. 卦位只描述「点亮 / 圆满 / 进度」，**严禁任何吉凶、方位宜忌、运势、改运语义**；
2. 文案禁区示例：「生门大开，今日宜出行」❌ → 「您家点亮了震卦，又添新福」✅；
3. 卦象象意（乾天、坤地等）仅作为卡面插画主题与成就名称的文化装饰，不与任何现实结果做因果暗示；
4. 卦位点亮条件必须真实对应产品内行为，**不得通过付费直接购买点亮**（大阵图不可氪金速成，保住「全家共同成就」的稀缺性）；
5. 上线前对八卦阵相关全部文案执行 §7 的迷信词扫描（新增扫描词：卦象、卦运、宜忌、生门、开门、吉位、凶位）。

### 3.10 解忧册（v1.5：电子答案之书 · 决断陪伴）

#### 3.10.1 功能定位

> **心里想着拿不准的事，翻开它，让它帮你把决定落下来。**

解忧册是「答案之书」形态的**决断陪伴工具**：用户带着一件犹豫的事来（要不要去、买不买、说不说、等不等），按住封面默念 → 松手翻页 → 得到一句**推动决断的话**。它不预测吉凶，它替用户把「想很久」变成「定下来」——这正是答案之书被验证的核心价值：**人不是缺答案，是缺一个替自己拍板的外部声音**。

产品价值分层：

| 层 | 价值 | 说明 |
|---|---|---|
| 情绪层 | 把纠结说出口 | 默念的动作本身就是倾诉，中老年无处安放的犹豫有了仪式出口 |
| 决断层 | 帮用户「定下来」 | 翻到的话直接给出行动方向（去/缓/放下/再想想），替代反复内耗 |
| 家庭层 | 给开口一个由头 | 翻到的卡可发给家人：「妈翻了本册子，说这事该问问你」——把独自纠结转化为家人商量 |

与现有功能的关系：福卡留日活（仪式）、转罗盘留时长（解压）、解忧册接住**情绪时刻**（意图驱动）——用户心里有事时会主动打开，是三个入口中唯一「被需要」型的。

#### 3.10.2 入口与导航定位

解忧册为**一级 Tab，居中放置**（详见 §5 页面结构）。独立成 Tab 的理由：

1. **被需要型入口配一级位**：解忧册是全产品唯一「用户带着烦恼主动打开」的功能，藏在二级页等于给求助的用户加门槛；
2. **心理空间隔离**：其余功能均为「家」的公共空间，而翻册的事往往私密。独立 Tab 是心理上的「小黑屋」——点这里 = 我现在只想自己待会儿；混在家族页里会模糊公共/私密边界；
3. **冷启动友好**：文案库不依赖家庭关系，未建家的新用户单机可玩，可能是最早建立产品印象的功能。

**Tab 图标与角标**：合起来的小红书（书脊轮廓），与罗盘、灯形成「每样功能都是一件实物」的国风系列感；**不使用红点**（无未读概念，红点会把它降格为消息工具）；柔性召回标记——翻过册的第二天，图标上给一片小竹叶（示意「今天又想点什么了？」），翻册后消失。

#### 3.10.3 核心流程

```
底部 TabBar「解忧册」（居中位）
  → 全屏一册线装书（封面：「解忧册」烫金三字）
  → 提示语：「心里想着那件拿不准的事，按住封面，想好了再松手」
  → 手指按住封面 → 封面泛起暖光，越按越亮（3 秒后轻提示「想好了就松手」）
  → 松手 → 翻页动画（1.5 秒，纸页声）
  → 出卡：一句推动决断的话 + 落款「解忧册 · 第 N 页」
  → 底部两个按钮：
      [ 就这么定了 ]  → 盖「定」字印章，本次决断记入「册子的记忆」（见下）
      [ 发给家人问问 ] → 生成分享卡，附一句「我翻到了这句，你怎么看？」
```

**交互细节**：

- 「按住 → 松手」与转罗盘「点住加劲」同一套按压肌肉记忆，一套组件两种玩法；
- 同一件事不重复翻：当日翻过一次后，按钮变为「明天再翻」——**稀缺才灵验**，翻一次就要认一次，这是答案之书区别于签筒的心理机制（防止变成反复抽签求上上签）；
- 「就这么定了」点下后全屏盖一个朱红「定」字印章动效（0.8 秒）+ 轻钟声——决断的仪式感闭环。

#### 3.10.4 册子的记忆（已定事项的降级形态）

记录不是档案功能，是**决断机制的一部分**：用户再次犹豫时翻看旧记录，等于书替 3 天前的自己作证——这是解忧册区别于「看过就忘的鸡汤」的根本。据此做四条降级设计，规避记录带来的隐私与心理负担：

| 规则 | 设计 | 理由 |
|---|---|---|
| **只留最近 3 条** | 第 4 条产生时最旧的自动沉底消失，无历史列表、无导出 | 防止「攒一堆没办成的事」变成新焦虑源；像翻旧书，翻过就翻篇 |
| **本地存储** | 仅存本机 storage，不上服务端、不进家庭数据、不上传云端 | 隐私红线：翻册的事（房子过户、子女婚事）一旦被家人看到即灾难；中老年手机常被子女翻看 |
| **位置在解忧册页内** | 翻完书的下方轻量展示，不放「我的」页 | 记录属于这本书，不是用户档案；避免与私密性冲突 |
| **轻确认，不推送** | 不发「该对账了」类提醒；仅在用户自然翻到旧记录时，条目旁给小按钮「这事办成了？」，点击盖小金印 | 多一条推送就多一分骚扰；「办成了」应是自然回访时的惊喜回收，不是任务 |

**「办成了」的情感价值**：用户点下小金印 →「这本书帮我定的事，成了 N 件」——这一刻产品从「翻着玩的册子」变成「我们家管用的东西」，是解忧册信任沉淀的核心时刻。N 的计数在本地累计，仅本人可见。

**合规补充**：册子的记忆与翻册行为数据（按住/松手事件）分开——前者本地、后者匿名埋点；文案页固定展示「翻过就翻篇，只留最近三条」。

#### 3.10.5 文案库规范（核心资产，决定产品成色）

文案必须**推动决断**而非预测结果。三类句式（初始各 40 条，合计 120 条起步）：

| 类型 | 作用 | 示例 |
|---|---|---|
| 促成句（该行动） | 推一把，别再拖 | 「想去就去，等来等去人就老了」「话说出口，事就成了一半」「这事您心里早有数了，去做吧」 |
| 缓行句（先等等） | 踩一脚刹车 | 「缓两天再说，急事最怕急办」「这周先不动，下周您再看看」「先睡一觉，明天想着还难不难」 |
| 放下句（别扛了） | 卸担子 | 「儿孙自有儿孙福」「这不是您的事，是老天的事」「操不了的心，就别操了」 |

**文案红线（强制，过迷信词扫描）**：

1. 禁用一切判断式断言：「能成 / 不行 / 会有 / 别去（指向结果凶险时）/ 注定 / 天意 / 预示 / 破财 / 有灾」；
2. 禁用与吉凶挂钩的表述，句句只指向**行动建议或心态调整**；
3. 不使用「命运 / 缘分注定 / 上天安排」等宿命词；「缘分」仅可用于「水到渠成、急不得」类的宽慰句；
4. 全部文案以「您」称呼，口语化，句长 ≤ 16 字，读出来像一位老朋友的话，不像签文。

#### 3.10.6 合规定位与审核口径

- **产品定位申报**：治愈系心理安抚工具 / 家庭互动（与福卡同一类目口径），不进入占卜算命类目；
- 与「答案之书」的公开区隔：官方介绍统一表述为「帮您把犹豫的事定下来的家庭陪伴册」；
- 翻页结果为**文案库随机**，客户端与服务端均不根据问题内容做任何匹配或个性化（技术上根本不采集问题内容——只采集「按住/松手」事件），杜绝「AI 听懂了问题」的预测暗示；
- 出卡页固定展示小字：「本册只宽心，只陪您拿主意」。

#### 3.10.7 数据指标（v1.5 新增）

| 指标 | 目标（上线 30 天） |
|---|---|
| 周活跃用户中使用解忧册的比例 | ≥ 15% |
| 出卡 → 点击「就这么定了」的转化 | ≥ 40% |
| 出卡 → 点击「发给家人问问」的转化 | ≥ 12% |

| 回访旧记录 → 标记「办成了」的转化 | ≥ 20% |

#### 3.10.8 埋点事件

## 4. 关键用户流程

### 4.1 新用户首日（黄金 60 秒）

```
家人群点开福卡分享链接
  → 微信授权（头像昵称，一个弹窗）
  → 直接看到「王家庄今天的福卡」+ 大按钮「我也要抽」
  → 摇一摇 → 翻卡 → 金光 → "您已为王家庄接福 +5"
  → 底部浮现「转发激活，为全家 +10」
  → 转发回家人群（用户已经在群里，成本为零）
```

**验收标准**：新用户从点开链接到完成第一次转发，≤ 4 次点击，零键盘输入。

### 4.2 裂变循环

```
王阿姨每日发福卡到家人群
  → 儿子小刘看到 → 进小程序 → 建立自己小家的关联
  → 王阿姨的门牌升级发到广场舞群
  → 老陈看到"满门福气"不服 → 拉自己全家建榜
  → 老陈的子女被拉入 → 循环
```

两条裂变链：
1. **福卡链**（每日高频，家族内纵向传播）
2. **门牌链**（低频高势能，家族间横向传播，决定增长天花板）

### 4.3 触点体系（两层通道 + 严格频控）

**技术前提**：小程序无默认推送能力，唯一消息通道为微信**订阅消息**（一次授权 = 一条下发额度，无额度不可发）。本产品为日活型（每日抽卡），通过「授权嵌入日常动作」使额度自然滚动——这是订阅消息在小程序内的唯一可持续打法。

**第一层：订阅消息（主力通道）**

| 时间 | 触点 | 频控 |
|---|---|---|
| 7:30 | 「今天的福卡到了」 | 每日 1 次 |
| 任意 | 「家人给您添福啦」 | 实时，但聚合推送 |
| 20:30 | 「全家人就差您没接福啦」 | 仅当日未抽卡用户 |

每人每日 ≤ 4 条（合规硬约束）。

**授权嵌入设计（额度的来源）**：

| 嵌入点 | 交互 | 用户心智 |
|---|---|---|
| 每次抽完福卡 | 结果页底部勾选区：「明天提醒我来接福」（默认勾选，可取消） | 「预约明天的事」，不是「授权推送」 |
| 添福 / 催福发送后 | 同上话术：「明天提醒我来看家人的福」 | 同上 |
| 生日簿开启提醒时（§3.7.6） | 「到时提醒我」按钮 | 一次性事件，一次授权一条，天然匹配 |

规则：
1. 授权勾选在用户完成正向动作**之后**出现（抽到卡的喜悦时刻），不在流程前拦截；
2. 用户拒绝授权不阻塞任何功能，仅在设置页可见提醒开关状态；
3. 额度耗尽时静默降级为站内提醒，不提示「授权失败」类挫败文案。

**第二层：内容回流（免费召回）**

家人群里的福卡卡片本身就是召回入口：王阿姨发出的卡 → 小刘在群里看到 → 点回小程序。设计上强化闭环：

- 福卡底部固定一行：「明天这个时候，回来接新的一张」；
- 生日当天福卡变生日卡，全家被内容拉回（不依赖任何推送）。

**保底：站内提醒**

用户主动打开小程序时，首页/家页顶部聚合展示「昨日错过的提醒」（家人添福、卦位点亮、家人消息），确保未授权用户不丢信息。

**远期演进项（不进当前版本）**：关联微信公众号承接低频高价值通知（生日提醒补位、未活跃召回）——待生日提醒规模上来且订阅额度缺口显现后再立项。

## 5. 页面结构（v1.5 起 3 个 Tab；个人内容并入「家」页）

```
TabBar（3 个，v1.5 调整）
├── 福签（首页）: 转罗盘 → 今日福卡 → 转发奖励 → 微任务确认
│    └── 页内下方：功能入口条（八卦集福阵 · 已点亮数 / 家庭生日簿 · 近期生日）
├── 解忧册（居中）: 按住默念 → 翻页出句 → 就这么定了 / 发给家人问问（见 §3.10）
│    └── 页内下方：册子的记忆（最近 3 条已定事项，本地存储，见 §3.10.4）
└── 家（合并页，吸收个人内容）:
     ├── 右上角：设置入口（提醒 / 隐私 / 家庭关系 / 动画与声音，见 §5.2）
     ├── 顶部：个人卡片（头像 · 昵称 · 连续火焰 · 个人福值与福禄挂件入口 · 奖状墙入口）
     ├── 子 Tab「我家 / 家族榜」
     │    ├── 我家: 家族福值池、成员状态墙、添福/催福、门牌展示、集福阵入口、近期生日入口
     │    └── 家族榜: 家内榜 + 好友家族榜（排名变动时子 Tab 红点）
     └── 降级说明: 个人卡片与子 Tab 分层排布，一屏先见个人状态 + 家族福值池，成员墙以下内容下滑查看

独立页
├── 建家流程页（家族名默认生成 → 邀请卡片）
├── 门牌/福卡分享预览页
├── 家庭生日簿页（v1.3）：生日录入、农历/公历对照、提醒设置、生日祝福入口
├── 八卦集福阵页（v1.4）：阵图主视图、卦位详情、圆满庆祝
└── 设置页（v1.5）：从「家」页右上角进入，内容清单见 §5.2
```

> 注 1：册子的记忆不设独立页面——它长在解忧册页内，是这本书的一部分（规则见 §3.10.4）。
> 注 2：不设「我的」Tab。个人状态（火焰、挂件、奖状）并入「家」页顶部个人卡片——个人状态本就是家庭的一部分，「我 + 我的家」一体呈现语义更完整。

**导航调整决策（2026-09-23）**：

1. 「我的家」与「家族榜」合并为「家」：二者同为家的公共空间（自家内部 / 家族之间），合并符合「家 = 一个地方」的心智，且少一个 Tab 降低误触；家族榜排名变动时以子 Tab 红点引导；
2. 解忧册独立成 Tab 且居中：全产品唯一「被需要」型入口 + 唯一私密空间，须与家族公共空间隔离（理由详见 §3.10.2）；
3. 不设「我的」Tab（3 Tab 结构）：连续火焰、福禄挂件、奖状墙并入「家」页顶部个人卡片，设置退至「家」页右上角入口。取舍依据：3 个大入口使中老年认知负担最小，但「家」页信息密度上升，需以分层排布 + 二级页分摊（奖状墙、挂件兑换为独立二级页）；设置入口右上角图标需做大（≥ 88rpx 触达区）并在首次进入时引导一次；
4. 首页（福签页）增加功能入口条：集福阵与生日簿入口以双卡片形式在首页常驻（罗盘与转发条下方），同时在「家 → 我家」子页保留完整入口卡片——入口双保险，确保不依赖滚动即达；入口条展示动态数据（已点亮卦数、距生日天数），本身即轻量召回位。

### 5.1 适老化设计规范（强制，沿用并强化）

| 项 | 规范 |
|---|---|
| 正文字号 | ≥ 17pt，核心信息 ≥ 22pt |
| 主按钮 | 高度 ≥ 88rpx，一屏 1 个主按钮 |
| 配色 | 高对比度；金色为主色调，喜庆但避免红绿并置 |
| 摇一摇 | 必须提供等效大按钮「点一下抽福卡」（不强制摇手机） |

| 文案 | 口语化、用"您"、零英文术语 |
| 动画 | 抽卡金光动画 ≤ 2.5 秒，可跳过设置（低端机） |

### 5.2 设置页内容清单（v1.5）

入口：「家」页右上角齿轮（触达区 ≥ 88rpx），首次进入「家」页时引导一次。设置项按「真实会想关/会想改」筛选，不做通用设置的搬运：

| 分组 | 设置项 | 默认值 | 联动规则 |
|---|---|---|---|
| **提醒设置** | 福卡推送（7:30） | 开 | 关闭后不影响家人给您添福的通知 |
| | 生日提醒（提前 7 天 / 3 天 / 当天，分别开关） | 关（用户主动开启） | 沿用 §3.7.6 规则，须先完成订阅授权 |
| | 催福接收 | 开 | 关闭后家人无法催您；催福按钮对发起方显示「对方已关闭提醒」 |
| | 频控透明化说明（只读展示） | — | 固定文案：「您每天最多收到 4 条提醒，不会多打扰」——将 §4.3 频控从暗规则变为用户知情权 |
| **隐私设置** | 隐身榜外 | 关 | 开启后本家族不出现在好友家族榜；沿用 §7 承诺 |
| | 生日记录可见范围管理 | 按条目保存值 | 快捷入口，跳转生日簿逐条管理 |

**明确不做**：语言切换、深色模式、字号调节（全局适老化已统一大字）、账号注销（入口放「关于」页法律链接，避免误触恐慌）。

## 7. 风险与合规（本产品最高优先级）

| 风险 | 等级 | 对策 |
|---|---|---|
| **微信审核：封建迷信类目** | 🔴 极高 | 全产品文案**只祝福不预测**：禁用"运势/吉凶/求签/算命/改运/挡灾/化解"，统一用"福卡/祝福/平安/福气"；福卡等级不与任何"命理"挂钩，仅是稀有度玩法；提交审核时以"民俗祝福、家庭互动"定位申报；**上线前做一次全文案迷信词扫描** |
| 诱导分享 | 🔴 高 | 微信禁止"分享后才能解锁功能"。设计口径：福卡**不转发也生效**，转发只是"额外 +10 福值"奖励——奖励分享而非强制分享，规避审核红线（对内文案可强化"为全家激活"的情感暗示，但产品逻辑上必须可完成） |
| 订阅消息骚扰 | 🔴 高 | 每人每日 ≤ 4 条；催福限 3 次/人/天 |
| **订阅消息额度耗尽（触点失效）** | 🔴 高 | 小程序无默认推送，一次授权仅一条额度。对策（见 §4.3 触点体系）：① 授权嵌入抽卡/添福等日常正向动作，额度随日活自然滚动；② 授权勾选默认出现且可取消，拒绝不阻塞功能；③ 额度耗尽静默降级为站内提醒；④ 生日类一次性提醒与「一次授权一条」天然匹配；⑤ 远期以关联公众号承接低频高价值通知（不进当前版本） |
| 医疗暗示 | 🟡 中 | 微任务只用生活化表述（喝水/散步/泡脚），禁用任何疗效词 |
| 道德边界 | 🟡 中 | 内部原则：可以放大"惦记家人"的情感，绝不制造"不转发家人会有事"的恐惧暗示；福卡文案库建立负面清单 |
| 隐私 | 🟡 中 | 家族榜仅好友可见；提供"隐身榜外"开关 |
| 生日信息处理（v1.3） | 🔴 高 | 生日信息仅用于农历日期换算、家庭生日簿和用户主动开启的提醒；默认不收集年份；保存前明示用途；支持编辑、删除和只我可见；不得用于画像、推广、榜单或自动化推断；上线前同步更新隐私保护指引 |
| 日期换算准确性（v1.3） | 🟡 中 | 服务端统一换算并覆盖普通日期、春节附近、闰月和年末边界测试；无法确认时提示稍后再试，不输出猜测结果 |

> ⚠️ 诱导分享条款需要特别注意：微信明确打击"分享后才能继续操作"。因此 3.2 节"转发才激活"必须实现为**软引导**（不转发福卡也计入家族福池，转发只是加成），文案说"为全家激活"是情感包装，功能上无强制。这是合规与增长设计的分界线。
