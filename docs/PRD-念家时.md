## 1. 产品定位

**念家时 · 家人生日提醒**——把重要的日子，记在心上。

双引擎产品：

- **引擎一：家庭纪念日管家（留存）**——记下家人生日、纪念日、在一起的日期，公农历换算，提前提醒，永不错过。解决「忘了爸妈生日会出事」的真实损失规避需求。
- **引擎二：仪式感内容工厂（裂变）**——针对母亲节/父亲节/七夕/生日等节点，用 AI 模板 3 分钟生成信纸/天数卡/时光胶囊等仪式感卡片，海报自带二维码分享至微信群和朋友圈，未注册好友扫码即可查看部分内容并互动。

**目标人群**：全人群。核心用户是 20-40 岁、离家在外、惦记家人但表达笨拙的子女（内容生产者与分享者）；受益人是不用装产品的父母/伴侣（内容接收者）。

**与 v1 的关系**：品牌、视觉、交互、目标人群全部推倒重来。仅保留：微信云托管部署架构、家族/成员数据模型、公农历换算逻辑、「福卡」降级为生日当天的表达层之一。

## 2. 为什么重做（v1 复盘 → 新假设）

### 2.1 「别点这个签」四个死因

| # | 死因 | 说明 |
|---|------|------|
| 1 | 心智被垄断 | 「集福」属于支付宝和春节，日常化没有心理场景 |
| 2 | 合规砍掉灵魂 | 禁迷信词后签文信息量为零，无情绪价值 |
| 3 | 家庭冷启动地狱 | 需要老人和子女同时装、同时活跃，无单边刚需撬动 |
| 4 | 无留存钩子 | 福值只涨不跌（对的），但没有「不做会损失什么」的回访动机 |

### 2.2 新假设

| # | 假设 | 承接设计 |
|---|------|---------|
| 1 | 忘记家人重要日子 = 真实损失（家庭矛盾/愧疚），规避损失的动机远强于攒福气的正激励 | 日子管家 + 倒计时 + 提前提醒 |
| 2 | 中国人情感表达含蓄，需要「体面的表达工具」代偿 | AI 感恩信、天数卡——替用户说出说不出口的话 |
| 3 | 节日是仪式感消费的天然峰值，借势比造势便宜 100 倍 | 节点日历横滑 + 节日横幅随日历自动换装 + 未上线模板可预约 |
| 4 | 社交裂变的本质是「分享者有面子，接收者有东西看」 | 海报成品自带品牌位与二维码；访客扫码免注册可见部分内容 |
| 5 | 时光胶囊制造「未来必回」的确定性回访 | 封存 → 开箱日横幅召回 → 开箱 → 分享开箱（二次裂变） |

### 2.3 验证指标（上线后 30 天）

- 北极星：**周活跃记日子用户数**（打开并查看/编辑过至少一个日子）
- 裂变：K 因子 = 每张海报平均带来的扫码访客数 × 访客→新用户转化率，目标 K ≥ 0.3
- 留存：次日留存 ≥ 25%，7 日留存 ≥ 12%
- 节点效率：母亲节模板预约→制作转化率 ≥ 40%
- 胶囊：埋下→开箱日回流率 ≥ 50%

## 4. 功能需求明细

### 4.1 日子管家（引擎一）

**FR-1 记一个日子**
- 类型：生日 / 纪念日 / 在一起（起始日后每天自动 +1）
- 输入零键盘：关系用标签点选（妈妈/爸爸/老伴/儿子/女儿/孙子/孙女/亲家/我自己 + 自定义）；月日用下拉选择
- 公历/农历互转：选任一侧实时换算另一侧 + 显示「X 天后」；农历支持下次落点换算（沿用既有生日簿算法）
- 可见性：家人可见 / 只我可见（默认家人可见，可改）
- 提醒：默认关闭；开启前弹授权说明（内容、频控、仅发给自己）；可选提前 7 天 / 3 天 / 当天，多选

**FR-2 日子列表与详情**
- 首页按最近倒计时排序；「在一起」类型固定列表底部，显示「第 N 天」
- 详情页：倒计时大数字（当天显示「就是今天 🎉」）；纪念日显示周年称谓（40 周年=红宝石婚）；祝福语点选即复制；「做一张卡片」直达模板；删除需确认
- 全部日子页：时间线（按月分组）⇄ 日历双视图切换；日历仅标记用户自己记的日子（不标公共节假日——空间记忆是「我们家的日子」）；点有日子的日期弹当日事件清单

**FR-3 提醒推送**
- 微信订阅消息；每人每日 ≤ 3 条；生日/纪念日当天 + 提前量由用户选择
- 当天提醒文案带行动建议（「今天是妈妈的生日 → 做一张专属福卡」）

### 4.2 模板馆（引擎二）

**FR-4 模板预览**
- 所有模板点击先进预览弹层：迷你成品（真实样式渲染）+ 特性标签 + 社会证明（人数/时长/免费）+ 场景化提示
- 已上线模板主按钮「✨ 开始制作」；未上线模板主按钮「🔔 上线提醒我」（预约）+「先收藏」

**FR-5 节点日历（借势营销）**
- 模板馆顶部节日卡横滑：母亲节/父亲节/七夕/春节…带倒计时，数据由服务端日历配置驱动，随日期自动更新
- 首页节日横幅同源数据；节日前 7 天开始展示
- 预约用户在模板上线/节日前 3 天收到推送（计入每日频控）

**FR-6 给妈妈的感恩信（AI 代笔）**
- 输入全部点选：写给谁（妈妈/岳母/奶奶/自定义）→ 你们的故事（多选：「她总给我留饭」「送我上学那些年」「她爱唠叨但都是好意」「她一个人把我带大」「我离家后她学会视频」）→ 语气（戳泪点/幽默/平淡）
- AI 生成：加载动画（≤ 2.5s）；产出 5 段式信件（开头、每个故事一段、语气收尾、落款）
- **逐句改稿**：信中每段可单独点换（每段 ≥ 2 个备选写法）；导航栏 🔄 整体重写
- 完成后进信纸海报（海报正文引用最终改定内容）

**FR-7 相伴天数卡**
- 关系（恋人/结婚/闺蜜/好友）→ 起始日期 → 样式（霞橘渐变/深夜星河/薄荷清晨）
- 天数每天自动 +1，「永不过期」的分享动机；实时预览

**FR-8 时光胶囊**
- 类型（给未来的自己/给未来的 TA）→ 开箱日（一年后/高考出分日/结婚纪念日/宝宝 18 岁）→ 封面提示语（「一年不见，你还挺想我吧」等）
- 封存后生成开箱邀请函海报；开箱日当天首页横幅召回；开箱页：摇晃动画 → 信件+照片揭示 → 双 CTA（我也埋一个 / 分享开箱）

### 4.3 海报与裂变

**FR-9 海报生成**
- 每类模板 1-3 套样式；固定品牌位（念家时 + slogan）+ 二维码（指向访客视图）
- 海报可保存图片、分享微信好友/朋友圈

**FR-10 访客视图（转化落地页）**
- 未注册扫码可见：天数等「体面内容」全量展示（分享者有面子）
- 打码钩子：「还有一段 TA 没发出来的话」渐隐遮罩
- **免注册解锁**：点亮 3 颗心（🤍→❤️，带进度提示「还差 2 颗」）→ 内容解锁。不强制授权、不强制注册（微信合规红线）
- 解锁后展示深色转化 CTA：「用念家时打开你们的照片 / 免费记日子做卡片埋胶囊」

**FR-11 我的卡片（二次裂变）**
- 每次生成/分享的海报自动存档（当日去重）；双列卡片墙；「再次分享」直接重出海报

### 4.4 通用

**FR-12 新用户空状态**：无任何日子时，首页保留节日横幅，日子区替换为引导卡（主 CTA 记日子 + 次选逛模板馆 + 「不用打字」顾虑消除文案）。

## 5. 非功能需求

- **合规红线**（继承 AGENTS.md，一票否决）：禁迷信词与结果断言；分享是奖励制非强制（无「不转发则如何」逻辑）；提醒默认关闭 + 每日 ≤3 条 + 订阅前说明内容；隐私最小化（不采集位置/通讯录/相册批量读取，AI 信件内容不含敏感个人信息上报）
- **AI 成本控制**：感恩信生成每日每人 ≤ 5 次；模板文案生成结果缓存复用
- **性能**：首屏（含空状态）≤ 1.5s；海报生成 ≤ 3s；AI 写信加载动画 ≤ 2.5s 且可跳过
- **视觉规范 v2**：暖白底 #fbfaf7 + 墨字 #1c1c28；主色霞橘渐变 #ff7a59→#ff4d6d；辅色雾紫 #6c5ce7 / 青金 #12b2a3；无衬线大字重，衬线仅用于天数数字；动画 ≤ 2.5s 且可跳过；`prefers-reduced-motion` 全量降级

## 6. MVP 分期

| 期 | 范围 | 验收标准 |
|----|------|---------|
| **MVP（首发）** | 日子管家全套（FR-1~3）+ 模板馆骨架（FR-4）+ 感恩信（FR-6）+ 天数卡（FR-7）+ 海报/访客解锁（FR-9~10）+ 空状态（FR-12）+ 改名提审 | 母亲节前上线；裂变链路全通（做卡→扫码→解锁→CTA） |
| **V1.1** | 时光胶囊（FR-8）+ 我的卡片（FR-11）+ 节点日历与预约推送（FR-5） | 胶囊封存→召回→开箱闭环可用 |
| **V1.2** | 家人空间（共享日子、家人瞬间照片流）、生日福卡表达层、周年称谓库 | 家庭内共享闭环 |
| **V2** | 结婚纪念日卡等垂直模板、模板 UGC/投稿、老照片修复拉新钩子 | 模板供给规模化 |

**首发前必须完成**：小程序改名（「念家时·家人生日提醒」，确认改名剩余次数、名称占用）、类目调整（工具>效率/日历）、微信后台简介与隐私保护指引更新。

## 7. 技术方案（映射既有资产）

### 7.1 前端：新建 `miniprogram-nianjiashi/` 目录

- **AppID 沿用现有**（走改名，不重新注册），`project.config.json` 指向现有 AppID
- 原生小程序框架；新视觉体系从零搭建，**不从旧目录迁移任何样式代码**（避免红金适老体系污染）
- 旧 `miniprogram/` 保留作参考；新目录上线、改名过审后，旧目录移入 `legacy/` 并加 README 声明废弃
- 新版双通道网络层沿用 `utils/request.js` 模式（云托管/本地切换）

### 7.2 后端：原地演进（Spring Boot 不新建）

- **复用**：登录链路（X-WX-OPENID→AuthService）、家族/成员/福值模型、部署（云托管+MySQL cloud profile）
- **删除**（收尾阶段，先改契约再删代码）：解忧册模块（JieyouService/QuoteLib/DTO/Entity、ApiController 端点、前端页面与 jieyou-storage、契约条目）
- **新增表**：`day_record`（日子，含类型/日历/可见性/提醒配置）、`made_card`（卡片存档）、`time_capsule`（胶囊，含开箱日/内容/邀请码）、`visitor_unlock`（访客解锁态，3 心计数）
- **新增服务**：海报渲染（服务端出图或前端 canvas + 服务端合成品牌位与带参二维码）、AI 信件生成（LLM 接口 + 每素材双写法缓存）、节日日历配置表
- 契约驱动不变：新接口先入 OpenAPI，走 Stage 2 checkpoint

## 8. 开放问题（开发前需拍板）

1. 海报渲染位置：服务端合成（清晰、可控制品牌位）vs 前端 canvas（省服务器、即时预览）——倾向前端 canvas + 服务端下发二维码链接
2. AI 供应商与预算：感恩信的 LLM 选型（云托管同厂 API 优先）及单次成本上限
3. 访客 3 心解锁的防刷：同一访客重复扫码是否重复计数（倾向 device 维度计数）
4. 「在一起」类型是否需要对方确认（单向宣告 vs 双向共建）——MVP 做单向，V1.2 家人空间时升级双向
