## 1. 产品概述

### 1.1 一句话定位

> **和家人组队打卡健康小目标，谁偷懒全家都知道。**

### 1.2 产品背景

- 三四线城市 45-70 岁「无聊中老年」人群：时间充裕、微信熟练、家族群活跃，但对健康管理有焦虑（血压、血糖、体重是饭桌常驻话题）。
- 现有健康类 App（Keep、薄荷健康）面向年轻人，操作复杂、无社交关系链，中老年用不起来。
- 该人群的转发动机是「维护关系」而非「彰显个性」：子女想关心父母但没有抓手，父母想被子女关注但没有由头。**「一起做一件事」正是两边都缺的连接点。**

### 1.3 要解决的问题

| 用户侧痛点 | 现状 | 我们的方案 |
|---|---|---|
| 父母知道该锻炼，但没有持续动力 | 三天热度，无人监督 | 家庭组队，偷懒会被"善意催一下" |
| 子女想关心父母健康，但开口只有"多喝水多运动" | 尬聊，被敷衍 | 看到父母实时打卡状态，有具体话题 |
| 健康目标太宏大（"我要减肥10斤"） | 挫败放弃 | 微目标：每天6000步、8杯水、22:30前睡 |
| 坚持了没人看见、没奖励 | 无反馈 | 电子奖状、健康之星排行榜、连续天数火焰 |

### 1.4 产品北极星指标

**每周活跃互助团数（Weekly Active Teams, WAT）**

一个团 = 一个家庭单元。团活跃意味着 2 人以上同时活跃，天然高于普通 DAU 含金量。

## 2. 目标用户画像

### 2.1 核心画像

**画像 A：王阿姨，58 岁，湖南岳阳，退休纺织厂职工**

- 每天刷微信 3 小时以上，家族群 4 个，广场舞队 1 个
- 手机里存着养生文章，转发前会犹豫"是不是谣言"
- 有高血压，医生嘱咐多走路，坚持了 3 天就放弃了
- 心理诉求：**想证明自己"身体还行、活得讲究"，想被子女夸**

**画像 B：小刘，31 岁，深圳打工，王阿姨的儿子**

- 每月回家 1 次，电话里只会说"妈你多走走"
- 给妈妈买过手环，她嫌麻烦没戴
- 心理诉求：**用一个低成本的方式表达孝心，缓解"不在身边"的愧疚**

**画像 C：老陈，63 岁，王阿姨的广场舞队友**

- 竞争心强，什么都想争第一
- 心理诉求：**排行榜上赢过老伙计**

### 2.2 用户角色关系

```
发起人（通常为子女，画像B）
   │ 拉新
   ├──→ 核心用户（父母，画像A）──┐
   │                            │ 互相监督
   └──> 扩散用户（舞友/亲戚，画像C）←┘
```

**关键洞察**：付费意愿最强的是子女（B），使用频率最高的是父母（A），传播最猛的是老伙计（C）。产品设计必须同时服务三者。

## 3. 核心玩法与功能需求

### 3.1 功能地图（MVP）

```
健康打卡互助团
├── 团队系统
│   ├── 创建互助团（团名、目标、成员上限8人）
│   ├── 邀请成员（微信分享卡片进团）
│   └── 团主页（今日全员打卡状态墙）
├── 打卡任务系统
│   ├── 预设任务（步数/喝水/早睡/吃早餐……）
│   ├── 每日打卡（一键打卡 + 自动同步步数）
│   └── 连续天数（火焰标识）
├── 互助机制
│   ├── 「催一下」（给未打卡的成员发提醒）
│   ├── 「点个赞」（给已打卡的成员点赞）
│   └── 代打卡提醒（子女可远程看父母状态）
├── 激励体系
│   ├── 电子奖状（周/月坚持奖，可保存分享）
│   ├── 团排行榜 + 好友排行榜
│   └── 团里程碑（全团连续7天→解锁祝福海报）
└── 分享裂变
    ├── 打卡战报卡片（发群里炫耀）
    ├── 奖状分享（朋友圈/群）
    └── 邀请进团卡片
```

### 3.2 详细功能说明

#### F1 互助团系统

| 字段 | 说明 |
|---|---|
| 团名 | 默认"XX家健康团"，可改，限 10 字 |
| 团目标 | 创建时从预设任务库勾选 1-3 项（步数/喝水/早睡…），全团统一 |
| 成员上限 | 8 人（家庭 + 舞友场景足够，避免大群难管理） |
| 团长 | 创建者，可修改团目标、踢人（简化 MVP：仅可解散） |

**F1.1 创建流程**

1. 首页点击大按钮「创建家庭团」
2. 选择 1-3 个健康目标（大卡片单选/多选，每项配大图标+一句俗语，如喝水——"一天八杯水，医生不来追"）
3. 填团名（默认生成，可跳过）
4. 创建成功 → 立即弹出「邀请家人」分享卡片

**验收标准**：从点开小程序到分享邀请卡，全程 ≤ 4 次点击，无需任何键盘输入。

**F1.2 邀请进团**

- 分享卡片文案：「老王家健康团邀请你：一起每天走6000步，谁偷懒全家催！」
- 新用户点卡片 → 授权登录 → **直接进入团主页**（不经过首页，新用户第一秒就在场景里）
- 团满 8 人后卡片变为"团已满员"

#### F2 打卡任务系统

**F2.1 预设任务库（MVP 固定 6 项）**

| 任务 | 目标 | 打卡方式 | 设计理由 |
|---|---|---|---|
| 每日健步 | 6000 步 | 授权微信运动自动同步，达标自动打钩 | 零操作，中老年最爱 |
| 喝水打卡 | 8 杯 | 每喝一杯点一下水杯图标（大按钮） | 高频互动，制造打开率 |
| 早睡打卡 | 22:30 前睡 | 睡前点「我睡啦」 | 制造晚间打开场景 |
| 吃早餐 | 每日 1 次 | 一键打卡 | 降低门槛的送分项 |
| 服药提醒 | 自定义时间 | 提醒 + 确认 | 高价值但需谨慎（见合规） |
| 广场舞 | 30 分钟 | 一键打卡 | 三四线特色，社交属性强 |

**F2.2 打卡规则**

- 每日 0 点重置；喝水按累计次数；其余为布尔打卡
- 步数任务：当日 24 点结算，达标即算（当天任意时间打开小程序都能看到实时步数）
- 打卡成功：全屏绽放动画 + 一句吉祥话（"坚持第 5 天，越活越年轻！"）
- 断签不清零，但连续火焰熄灭（降低挫败感：中老年用户断签后直接流失是最大风险）

**F2.3 补签（V1.1）**

- 每月 2 次免费补签机会，防止一次遗忘导致放弃整个产品

#### F3 互助机制（产品灵魂）

**F3.1 「催一下」**

- 团主页每位未打卡成员旁有醒目「催一下」按钮
- 点击 → 对方收到**微信服务通知**（订阅消息）：「老伴儿，王阿姨喊你去走路啦！」
- 每人每天对同一成员最多催 3 次（防骚扰）
- 文案库轮换，语气必须**善意、俏皮**，绝不能是批评感："再不走，广场舞C位就是老李的了！"

**F3.2 「点个赞」**

- 已打卡成员可被点赞，点赞以大拇指/爱心形式累积显示
- 被点赞方收到通知：「儿子给你今天的6000步点了赞！」← **这是全产品情感价值最高的时刻，文案必须打磨**

**F3.3 子女视角「远程看护」**

- 团主页用颜色区分状态：绿色=已打卡，灰色=未打卡
- 连续 3 天全灰的成员，系统自动给其"子女辈"成员（关系标签）推送关怀提醒：「张大爷 3 天没打卡了，打个电话问问？」
- MVP 简化：不做辈分识别，推送给团长

#### F4 激励体系

**F4.1 电子奖状（核心传播物）**

- 触发条件：个人连续打卡 7/21/100 天；全团全员连续 7 天
- 样式：红底金字，大号姓名，"特发此状，以资鼓励"的仪式感排版（**审美必须对标学校奖状，不是互联网风格**）
- 可保存到相册、直接分享朋友圈/群
- 奖状右下角带小程序码 → 扫码直接进团（裂变闭环）

**F4.2 排行榜**

- 团内榜：本周打卡天数排名（团内攀比，安全区）
- 好友榜：微信好友间排名（广场舞队友互相较劲的主战场）
- 排行榜展示文案示例："本周你排第 2，老陈已坚持 6 天，就差你 1 天！"（制造追赶动力）

**F4.3 团里程碑**

| 里程碑 | 奖励 |
|---|---|
| 全团连续 7 天 | 解锁专属祝福海报（全家福风格模板） |
| 全团累计 100 天 | "健康之家"电子门牌（可设为群头像） |
| 全团累计 365 天 | 年度健康报告（全家每个人的坚持曲线图） |

#### F5 分享裂变设计

| 分享物 | 触发时机 | 目标 |
|---|---|---|
| 邀请进团卡 | 建团后、团成员页 | 拉新（核心链路） |
| 每日打卡战报 | 打卡成功后 | 群内炫耀，召回 |
| 电子奖状 | 达成成就时 | 朋友圈传播，扫码进团 |
| 团里程碑海报 | 全团达成时 | 全员自发转发 |

**K 因子目标**：每个活跃团每月带来 ≥ 0.5 个新团（MVP 阶段人工验证）。

## 4. 关键用户流程

### 4.1 新用户首日流程（黄金 60 秒）

```
点开分享卡片
  → 微信授权（仅头像昵称，一个弹窗）
  → 直接进入团主页（看到自己和"绿色成员"）
  → 弹层提示"今天还没打卡哦"+ 大按钮「立即打卡」
  → 点击 → 放大动画 + 吉祥话
  → 底部浮现「邀请更多家人」
```

**原则**：新用户完成第一次打卡前，不出现任何非必要界面。

### 4.2 裂变循环

```
子女建团 → 拉父母 → 父母打卡 → 父母拉舞友 →
舞友建新团 → 拉自己子女 → 子女建团 → ……
```

关键裂变引擎是 **"父母的奖状发到家族群/朋友圈 → 同龄人扫码"**，因此奖状质量决定增长上限。

### 4.3 留存钩子（每日三触点）

| 时间 | 触点 | 方式 |
|---|---|---|
| 早 7:30 | 今日任务提醒 | 订阅消息 |
| 午/晚任意 | 好友点赞/催一下 | 订阅消息 |
| 晚 21:00 | 「团里还有 2 人没打卡，去催一下」 | 订阅消息（仅团长，控制频次） |

## 5. 页面结构（MVP 共 5 页）

```
TabBar（3个）
├── 团主页（首页）: 成员打卡状态墙 + 今日任务入口
├── 打卡页: 6 大任务卡片，大按钮交互
└── 我的: 连续火焰、奖状墙、排行榜、邀请家人

独立页
├── 建团流程页（选择目标 → 团名 → 邀请）
└── 奖状预览/分享页
```

### 5.1 适老化设计规范（强制）

| 项 | 规范 |
|---|---|
| 正文字号 | ≥ 17pt，核心信息 ≥ 22pt |
| 主按钮 | 高度 ≥ 88rpx，一屏不超过 1 个主按钮 |
| 配色 | 高对比度（深字浅底），避免红绿组合（色弱） |
| 交互深度 | 任何功能 ≤ 3 次点击到达 |
| 文案 | 口语化，用"您"，禁用英文术语（"授权"要说"允许"） |
| 输入 | 全流程尽量零键盘输入（团名默认生成） |
| 反馈 | 所有操作有放大动画/震动反馈，明确告知"成功" |

## 6. 数据指标体系

### 6.1 北极星与护航指标

| 层级 | 指标 | MVP 期目标（上线 30 天） |
|---|---|---|
| 北极星 | 周活跃团数 WAT | 验证型：≥ 100 |
| 裂变 | 每团带来的新团数 | ≥ 0.3 |
| 裂变 | 分享卡片打开率 | ≥ 25% |
| 留存 | 次周团留存率 | ≥ 40% |
| 参与 | 团均成员数 | ≥ 2.5 |
| 参与 | 人均周打卡天数 | ≥ 3.5 |
| 情感 | 「点个赞」日均使用次数/团 | ≥ 1（衡量产品是否产生真实互动） |
| 风险 | 通知退订率 | ≤ 10% |

### 6.2 埋点关键事件

`进团成功 / 打卡成功 / 催一下 / 点个赞 / 奖状生成 / 奖状分享 / 邀请卡分享 / 邀请卡打开`

## 7. 风险与合规

| 风险 | 等级 | 对策 |
|---|---|---|
| 医疗暗示红线 | 🔴 高 | 任务库只用"多走路、多喝水"等生活化表述；**禁用**"降血压、降血糖、治疗、理疗"等词；服药提醒定位为"生活提醒"而非医疗功能，文案注明"不构成医疗建议" |
| 订阅消息骚扰 | 🔴 高 | 严格频控（每人每日 ≤ 4 条），文案温柔；催一下防刷 |
| 微信步数授权失败 | 🟡 中 | 授权失败时降级为一键手动打卡，绝不阻断 |
| 中老年挫败流失 | 🟡 中 | 断签不清零、每月免费补签、失败文案永远鼓励 |
| 隐私 | 🟡 中 | 步数等数据仅团内可见；排行榜默认仅好友可见；提供"退出排行榜"开关 |
| 适老化审核 | 🟡 中 | 提交微信审核时申请"适老化版本"说明 |

## 8. 版本规划

| 版本 | 范围 | 目标 |
|---|---|---|
| **MVP (v1.0)** | 建团/进团、6 项任务打卡、催一下、点个赞、周奖状、团内榜、邀请卡分享 | 验证"家庭互助打卡"是否成立，跑通裂变闭环 |
| v1.1 | 补签、好友排行榜、里程碑海报、订阅消息频控优化 | 提升留存 |
| v1.2 | 年度健康报告、团相册（打卡晒照）、语音鼓励（30 秒语音点赞） | 强化情感价值 |
| v2.0 | 广告变现（激励视频解锁奖状模板）、子女付费"孝心会员"（高级奖状模板、专属提醒） | 商业化验证 |

**MVP 明确不做**：支付、提现、实物奖励、自定义任务、私信聊天（用微信群）、AI 建议。

## 9. 评审决策记录（2026-09-04 已确认）

| # | 问题 | 决策 | 依据 |
|---|---|---|---|
| 1 | 服药提醒是否进 MVP？ | ❌ 不进，V1.1 再上 | 合规敏感，MVP 先验证核心闭环 |
| 2 | 团长是否允许踢人？ | ❌ MVP 不支持踢人，仅支持解散团 | 家庭场景踢人伤感情 |
| 3 | 一人可加入几个团？ | MVP 限 1 个团 | 聚焦家庭场景；V1.1 开放多团（舞友场景） |
| 4 | 订阅消息模板类目报备 | 列为开发前置任务（见 9.2） | 微信侧审批有周期，需尽早提交 |
| 5 | 冷启动策略 | ✅ **家族群内测** | 种子用户信任度高、反馈真实、无地推成本 |

### 9.1 冷启动执行计划（家族群内测）

**阶段一：种子期（第 1-2 周）**

- 团队成员各自家族群投放，目标 5-8 个群、约 100-150 名用户
- 专人值守群内反馈，收集「看不懂 / 点不到 / 卡住」三类问题，48 小时内修复
- 观察指标：邀请卡打开率、首次打卡完成率

**阶段二：验证期（第 3-4 周）**

- 验证裂变链路：奖状是否被自发转发、是否有家族群外的新团出现
- 观察指标：每团带来的新团数、次周团留存率
- 决策点：若「每团带来新团数 ≥ 0.3」且团留存 ≥ 40% → V1.1 期启动广场舞队小规模地推；否则先迭代产品再扩量

**阶段三：扩量期（第 5 周起）**

- 复盘内测数据，确定是否申请正式推广资源

### 9.2 开发前置任务清单

- [ ] 微信小程序账号注册 + 类目选择（健康/生活类，避开医疗类目）
- [ ] 订阅消息模板报备：打卡提醒、点赞通知、催一下、关怀提醒（4 个模板）
- [ ] 微信运动数据接口权限申请
- [ ] 奖状视觉设计（对标学校奖状风格，红底金字）
- [ ] 内测数据埋点方案评审
